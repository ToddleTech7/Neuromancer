# 评审报告：采集 / 回放 / 派生

日期：2026-10-29 · 范围：本仓库当前实现与文档 · 结论只针对这个版本

## 结论

1. **主线方向是对的**：服务端 op log 管“编辑结果”，本项目采“过程”；原始/派生/人工表达分开；回放用录制时的完整 state 与视口。这些判断比工具本身更有价值。
2. **真正的缺口不是功能，而是 C0**：公开数据上的采集→落包→派生→回放已经跑通；真实 CAVE 的一次真人会话仍未发生。当前所有“已验”都是机制验证或公开数据验证，不能替代现场。
3. **实现里有一批确定性 bug，不是理念问题**：草稿删不掉、草稿/回收站会被当成最新包、128 MB 上限下长会话存不进去、结束关键帧来不及进包、`--seek-t` 拿下一个锚点做期望值、图层从来没有被清过、uint64 段 ID 在 JS 里丢精度、静态 HTML 对新事件名显示原始 JSON。本次已修其中大部分（见 §四）。
4. **文档的主要问题不是“少”，而是“旧、重、互相矛盾”**：22 篇 md / 约 6,000 行，开发记录 220 KB；同一个数字有 107/136/141/142 多个版本；同一件事（覆盖、端口、默认采样、注入路线）在不同文档里有不同说法。防御性表述很多（文档+代码里“如实”约 94 次、“必须”约 185 次，其中文档本身“如实”约 48 次），但真正该说清的 C0 计划反而很少。
5. **从你的出发点看，下一步应当是“收口”而不是“加功能”**：一次真实 1 小时会话 + 保存/恢复/回放/对 op log 的闭环，优先于 provider、UI 状态、私有 journal、更多回放入口。

## 功能设计评价

### 成立的部分

| 设计 | 为什么成立 |
|---|---|
| 服务端 op log 与客户端过程分开 | 结果与过程是两种证据；混在一起会让“提交过”冒充“当时在看” |
| 原始事件 / 派生 / 人工备注三分 | 派生可重算，原始可审计，备注不冒充程序事实 |
| 每个 state-change 带完整 state | 回放单位是“时刻”，不是“30 秒窗口”；这是复刻主线的关键 |
| 图 ↔ state 用 `state_sha` 构造绑定 | 不靠时间猜；快门时同步取 state，缺失就随图存 |
| 回放用录制视口 | 像素投递对尺寸敏感；这是实测出来的硬约束 |
| 动作有效性地板 | 防止“两边都没动”被当成通过 |
| 不可比帧单列 | `painted_partial`/`motion_lag`/`pixel_unstable` 不混进均值 |

### 过度扩张的部分

| 现状 | 代价 |
|---|---|
| 4 条回放入口（`replay_manual_session` / `cave_replay_viewer` / `cave_replay_studio` / `verify_replay_fidelity`） | 判据、产物、文档各写一遍；用户不知道该信哪个 |
| 3 条注入 + 油猴/控制台残留 | `--open`/`--cdp` 已够；`/install` 与油猴文档已被删除，但代码和输出还在，读的人会以为它是主路 |
| 3 条保存路径（HTTP、宿主直写、控制台） | 失败分支多；413/500 的宿主回退此前没接上 |
| 30+ 事件类型（`ui.state`、`ext.snapshot`、`private.journal`、`api.capability`、`edit.*`） | 大部分依赖未验证的私有端点；真实站点一次都没跑过 |
| `功能清单` + `当前进度` + `采集内容` + `关键帧规则` + 模块页 | 同一能力至少两处描述，数字一改就漂 |
| 开发记录 2,524 行 | 对新接手的人是噪声；历史决策应提炼，不应按天堆 |

判断：**采集与 state 回放是核心，派生是后处理，工作台是查看器**。其余能力在 C0 之前都属于可选项，不应继续扩张。

## 实现 bug（本次已修）

| # | 问题 | 证据 | 处理 |
|---|---|---|---|
| 1 | 草稿永远删不掉 | `_drop_draft` 对 `shots/` 子目录调用 `unlink`，抛 `IsADirectoryError` 后被吞；`results/manual_sessions` 里保存成功的 `sess_...sgesl` 仍有同 session 草稿 | 改 `shutil.rmtree`，补测试 |
| 2 | 草稿/回收站会被当成最新包 | `nx.latest_pack`、`cave_manual_server._latest_pack`、`list_pack_dirs`、`newest_pack_since` 只按目录名/时间取；复现时 `_draft_*` 被选中 | 统一过滤：必须有 `manifest.json`，跳过 `_draft_*`/`_trash`；`inspect_pack`/`recover_draft` 跟随 `NM_SESSIONS` |
| 3 | 长会话存不进去 | `/save` 上限 128 MB；超过返回 413，`manual_boot` 只显示“保存失败”，不触发宿主直写；1 小时语义图可达 100–400 MB | 413/500 也置 `__caveSaveRequested`，走宿主 `_host_save` |
| 4 | “结束并保存”的关键帧来不及进包 | `checkpointNow('session_end')` 启动异步 `captureShot`，紧接着 `stop`/导出 | recorder 保存 `lastCheckpointShot`；面板先 await 再导出 |
| 5 | `--seek-t` 拿下一个锚点做期望值 | 重放到 cut，却拿 `a1`（下一检查点）比 position/像素；中途停止必误判 | 用 cut 时刻最近完整 state 构造期望锚点；去掉 `stop_at` 截断逻辑 |
| 6 | 单锚点可以产生空 PASS | `--start == --end` 或 seek 超出最后锚点后 `len(anchors)<2`，循环不跑，`0/0` 判 PASS | 裁剪后强制 ≥2；seek 超出最后锚点时用最后 state 作为期望 |
| 7 | 图层从来没有被清过 | `_apply_state` 用 `s.layers.keys()`，但 `Layers` 没有 `keys()`；异常被吞 | 改 `s.layers.clear()`；state 有 `layers: []` 时真正清空 |
| 8 | uint64 段 ID 丢精度 | `LIVE_FP_JS` 对 `segments` 做 `Number()`；minnie65 root id 约 8.6e17 > 2^53 | 保留十进制字符串，Python 侧 `int()` 精确比较；去 `!` |
| 9 | 静态 HTML 对新包显示原始 JSON | `event_line` 只认旧名 `state_sample`/`pointer`/`note`；新包是 `viewer.state-change`/`input.pointer`/`evidence.bookmark` | 统一走 `ctype`，补齐新事件格式 |
| 10 | “注意点时间线”没有选中集 | `attention_rows` 读 `selection.change.layers`，实际字段是 `selection`；且用最后一组值回填所有行 | 改读 `selection`，按时间维护当前集合 |
| 11 | 工作台时间轴漏 `session.end`/备注 | `EVENT_TYPES` 写的是 `session.stop`/`note.added` | 改 `session.end`/`evidence.bookmark` |
| 12 | 回放启动可能 0.5 s 超时 | `set_default_timeout(500)` 之后 `wait_for_function` 没显式 timeout | 显式 60 s |
| 13 | 页面忙时像素比对崩 | 12 次读回全失败时 `any_best` 为 None，随后取下标 | 允许 `None`，标 `pixel_unstable` |
| 14 | Windows 回放直接崩 | `signal.SIGALRM`/`setitimer` 在 Windows 不存在 | 无 SIGALRM 时退化为普通 evaluate（无硬超时） |
| 15 | 草稿丢图↔state 绑定 | `flushDraft` 与 `_write_draft` 的 shot 白名单没有 `state`/`content`/`paint_*` | 两处补齐；恢复包保留绑定与内容判据 |
| 16 | 公网兼容测试永远失败 | `verify_cave_recorder_public.py` 用旧事件名统计 `session_start/stop` | 改用 `csp.ctype` 统计 `session.start/end` |
| 17 | 真实 /save 的 provenance 全是 unknown | `/save` 调 `pack_session` 不传 `legs`，即使 `client_process` 是本地录的 | `/save` 与宿主直写标 `client_process=real`；恢复同理 |
| 18 | 尾段静默丢失 | `_all_idle_segments` 只配对相邻输入，最后输入→session.end 不算 | 传入 session.end，补尾段 |
| 19 | join 的 op_id 类型不一致会漏匹配 | op log `op_id` 可能是 int，recorder 是 string（或反之） | 索引统一 `str()`，保留 raw 回退 |

## 实现 bug（仍开放，按优先级）

> 2026-10-30 新增：`replay_manual_session` 原先用 state 单位（体素）当 nm 打印，导致“整段 6/6 PASS”是单位错误。修正后 89s 包整段 4/6（末段 107.56nm >60）；首个检查点段 3/3（15.19nm）。v1 的推荐验收是**分段** `--start/--end`，不是默认整段。

### 明确矛盾（文档已改；行为改动见括号）

1. **“同名不覆盖” vs `_unique_dir` 同一 session 覆盖**：`modules/会话包与关联` 与 `results/README` 曾写“不覆盖”，测试 `test_same_session_overwrites` 却锁定覆盖。

8. **删除“移到 `_trash`” vs 真删**：测试注释曾写 `_trash`，代码和 UI 是真删（已改注释）。

### 过度防御 / 过度琐碎

- `docs/` 约 6,000 行，开发记录 2,524 行 / 220 KB；文档+代码里“如实”约 94 次、“必须”约 185 次、“不能”约 130 次；“不假装/不冒充/不推断”约 36 次。
- 五个不变量本身是好的；但每个模块页再重复一遍，`当前进度`、`功能清单`、`采集内容` 又各讲一遍，读者要自己拼。

## 从你的出发点：还缺什么

你的起点是“采到真实校对过程，之后能回看、能分析”，不是“做一个采集平台”。按这个标准：

### 必须做（C0）

1. **一次真实 1 小时会话**：真人、真 CAVE/NG、真数据源、真鼠标。用 `nx.py collect` 或 `--cdp`，中途打 3–6 个检查点，写 1–2 条备注，结束并保存。
2. **现场验收 7 条**：
   - 保存后目录完整（事件/图/备注/manifest）；
   - 重开 `打开.html` 能看轨迹与事件；
   - `nx.py replay` 能只喂输入复现 3 段以上；
   - 关键帧与 state 对得上（`captured` 为主）；
   - 选中集/图层切换能回放；
   - 关窗/断网/保存失败不阻断校对；
   - 真实 op log 能 join 上至少一条（若有导出）。
3. **保存规模实测**：1 小时、语义图默认开，确认包大小与 128 MB 上限；若接近上限，先走宿主直写/分卷，不要等到现场丢数据。
4. **真实站点四件事**：登录态/`--profile`、https 混合内容、CSP/iframe、graphene 的 `source` 对象与 uint64 段 ID。
5. **数据治理**：知情同意、截图是否含敏感信息、保留期、备份位置。这些不是代码问题，但必须在第一次真实采集前定。

### 应该做（C0 后，按证据）

- `picked` 真机命中：用真鼠标，不再用合成事件扫点。
- 一次真实 op log 导出，验证 `exact-anchor`/`anchor-estimated` 的边界。
- 版本指针：录制时的 seg/EM/mesh 版本；没有它，回放只能叫“当前数据上的复刻”。
- 图层样式回放：至少把 `selectedAlpha`/`notSelectedAlpha`/`baseSegmentColoring` 映射进去。
- 大 state 的降级策略（`state_truncated`），先在真实 graphene 包上量。

### 暂时不要做

- 更多 provider/`ext.snapshot`/`private.journal`/`ui.state` 的扩展；真实站点还没确认键名与格式。
- 更多回放入口；先把 `nx.py replay` 和 `nx.py studio` 两条命令路径走通。
- L1 工作段、多版本阈值、PP08/PP09 的语义标签；这些是后处理，且需要真实数据才有意义。
- 再写一份“全量设计”文档；先把现有文档的数字与矛盾收敛。

## 建议的两周顺序

| 天 | 做什么 | 完成标准 |
|---|---|---|
| 1 | 备份当前 `results/manual_sessions`；跑一次 1 小时公开数据“加压会话” | 包 >100 MB 也能保存；草稿清理；恢复可用 |
| 2 | 真实 CAVE 接入彩排（登录、profile、https、iframe、graphene） | 页面左下出现面板、事件计数增长、关键帧非黑 |
| 3 | 真人 1 小时 C0 | 包完整；`打开.html` 可看；`nx replay` 至少 3 段位置/选中一致 |
| 4 | 真实 op log 导出 + join | 至少一条 exact-anchor；不确定的标 estimated/window |
| 5 | 根据 C0 结果删功能/删文档 | 只留被真实数据证明有用的字段与入口 |
| 6–10 | 修 C0 暴露的问题（版本指针、picked、样式、大 state） | 每项有真实包上的证据 |
| 11–14 | 冻结采集契约，写数据卡与导出格式 | 新同事能按文档复现一次会话 |
