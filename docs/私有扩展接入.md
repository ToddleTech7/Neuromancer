# 私有 NG 前端的接入清单（待补充 / 已能采 / 怎么接）

更新：2026-10-29　状态：**接入草案**
依据：`Neuroglancer私有扩展与采集回放能力_代码核查回复.md`（2026-10-28 静态核查）
+ 当前 recorder 的实际字段。

> 用途：把“他们前端有、但我们还没采”的东西列清楚，标出接入方式与代价，
> 方便拿到真实 graphene 环境后按顺序补，不用重新调研。

## 0. 一句话前提

我们的 recorder 只依赖两样东西：**`viewer.state.toJSON()`** 和 **DOM/输入事件**。
所以：

- state 里有的 → 我们**已经采到**（只是可能没单独提出来）；
- 只在内存/私有对象里的 → 我们**采不到**，必须对方暴露 hook、或我们 patch 私有类（脆弱）；
- 只在 localStorage/请求头里的 → **能读，但要标“私有实现、版本相关”**。

## 1. 已能采到（现状，不需要改）

| 数据 | 来源 | 我们的字段 |
|---|---|---|
| 输入（拖/滚/键/修饰键） | DOM 监听 | `input.pointer/wheel/key` |
| 视角（位置/缩放/朝向/布局） | `state.toJSON()` | `viewpoint`（每次 state-change） |
| 选中集（**全量**） | `layers[].segments` | 进去重 sig；完整列表随 `state_sample.state` 落盘 |
| 选中集（摘要，每层前 8 个 id + count） | `viewer.layerSelectedValues` | `selection.change`（`selection_sample`） |
| 图层可见性/透明度 | `layers[]` | `layerInfo()`（name/type/visible/opacity） |
| **Multicut 草稿**（sources/sinks） | `layers[].multicut` | `draft.update`（`multicut_change`，已单独成事件） |
| Merge / FindPath 草稿 | `layers[].source.state` | **只在完整 state 里**（没单独事件）；公开 precomputed 数据源的 `source` 是字符串，没有 `state`，这条路径在本机测不出来 |
| 鼠标落点/命中 ID | `viewer.mouseState` | `viewer.focus`（position/page/pickedValue） |
| 画面 | `canvas.toDataURL()` | `keyframe.capture` + `shots/*.png` |
| **界面状态**（面板尺寸/工具栏/通知） | DOM（v1.2 已做） | `ui.state`：`ui.panels[]` 每个 pane 的 `[x,y,w,h]`、`ui.tool.palette_open`/`items`、`ui.notices[]` |
| 提交请求 | fetch/XHR 钩子 | `api.request` / `api.ack`（URL/body/状态） |
| 停留 | 我们的检测 | `viewer.dwell`（中心+选中+可见层不变 ≥5s） |
| 缺口/丢弃 | 我们的检测 | `gaps[]` / `overflow` / `seq` 断档 |

### 1.1 采了但下游用得浅

先纠正一个说法：**没有“完全没人看”的字段**，容易被说成没人看的是下面这两个：

| 数据 | 到底谁在用 | 结论 |
|---|---|---|
| `selection.change`（每层前 8 个 id） | `cave_join.collect_selection_ids()` 用它收候选 id 去对 op log；`build_context()` 统计提交附近的选中次数；`cave_session_replay` 时间轴会展示 | **在用**，只是每层 8 个是下界（已在 join 报告里写明）。全量在 `state_sample.state.layers[].segments` |
| `viewer.focus`（鼠标悬停位置的 `pickedValue`） | `cave_session_pack` 只做类型映射；`cave_session_replay` 时间轴把位置**打印出来**（纯展示）；join / 派生 **不读** | **用了但没分析**：目前只是“能看到指针在哪”，没人拿它算东西 |

所以真正的问题是：

1. **`viewer.focus` 的量不小**（实测 166 s 会话里 97 条，比 `viewer.state-change` 的 68 条还多），
   但同等的“在哪看”信息 `state_sample.viewpoint.position_nm` 已经有了；
2. 它的独有价值在于 `pickedValue`（**指针下的段 ID**），这个是 position 给不了的；
3. 如果暂时不用，要么在派生层做成“指针停留段的频次表”，要么在文档里标成**仅存档**，
   读到了也要标注口径。

## 2. 能采但还没采（补起来便宜，P0/P1）

| # | 缺什么 | 为什么要 | 怎么接（改哪） | 成本 |
|---|---|---|---|---|
| P0-0 | **对象型 `source` 整条丢失**：`layerInfo()` 只认字符串和数组，`l.source` 是对象时返回 `null` | graphene 图层的 `source` 就是对象（`{url, state}`）。现在图层摘要里**看不到数据源**，只剩图层名。这是 bug 不是缺功能 | `layerInfo()` 里加：`source_detail`（对象取 `{url,has_state}`，数组逐项取 `.url`）+ `has_state`（有无 `state`），**不复制 state 本体** | 8 行 |
| P0-1 | **图层样式**：`baseSegmentColoring`、`baseSegmentHighlighting`、`selectedAlpha/notSelectedAlpha/objectAlpha`、`colorSeed/segmentColors/segmentDefaultColor` | 回放时颜色/透明度不同，像素比对会差 | `layerInfo()` 里加这些字段（它们就在 `layers[]`）；随 `viewpoint` 走，不改事件结构 | 20 行 |
| P0-2 | `showSlices`、`partialViewport`、`crossSectionDepth` | 布局/切片可见性影响画面 | 在 `extractViewpoint()` 里从 `js` 取，加到 `vp` | 10 行 |
| P0-3 | **Merge / FindPath 草稿摘要事件** `draft.state`（multicut 已有 `multicut_change`，不用重做） | 现在只在完整 state 里，分析要翻 JSON；单独成事件后派生/看包直接可用 | `sampleState()` 里读 `layers[].source.state`，变化时 `emit('draft.state', …)`（只放摘要，id 转字符串；没变不发） | 30 行，**需 graphene 包验证** |
| P0-4 | **完整 state 的 256 KB 上限**（`MAX_FULL_STATE_BYTES`）在 graphene 上够不够 | 超限时 `state_omitted='too_large'`，**整条 state 丢掉**——草稿、图层配置、选中集全没，只剩 `viewpoint` 摘要。公开 minnie65 实测只有 **726 B**，离上限很远，但 graphene 带 `source.state` 会大得多，没测过 | 先测真实 state 字节数；超了就改“超限时只保留图层骨架（去掉 `source.state` 大字段）+ 标 `state_truncated`”，不要整条丢 | 20 行，**需真实环境** |
| P0-5 | **多 panel 的尺寸/投影**：`viewportInfo()` 只取**面积最大的那一个 canvas** | split view（2D+3D 并列）时只知道一个 panel 的大小，其余 panel 的尺寸与投影全丢——回放对不上分屏比例 | **已做（v1.2）**：`ui.state.ui.panels[]` 记每个 `.neuroglancer-rendered-data-panel` 的 `[x,y,w,h]`，实测 4 个 pane 各不相同。投影矩阵仍未记（需真实 split 3D 才能定取值） | 已完成 |
| P1-1 | 私有本机记录：`localStorage['neuroglancer-graph-edit:<graphUrl>']`、`['neuroglancer.brush-merge.v1:<graphUrl>']` | 这是他们唯一持久化的“提交保护/batch 进度”记录 | **已做（v1.4）**：`pollJournal()` 5s 一次扫这两个前缀 → `private.journal`（`key`/`bytes`/`sha`，≤2000 字存正文，超了存 `value_head`）。实测假键→落盘 ✓；**真实键名待现场确认** | 已完成 |
| P1-2 | 提交头的组/步骤：`X-CAVE-Edit-Group / Step / Request-ID` | 现在只知道“发了一次 merge”，不知道属于哪个组、第几步 | **已做（v1.4）**：`readHeader()`/`editHeaders()` 在 fetch（含 `Request` 对象）与 XHR（`setRequestHeader`）两路都解析，写进 `edit.request.edit_group/edit_step/edit_request_id`（**与本地 `request_id` 分开命名，不同源**）。实测假头→落盘 ✓ | 已完成 |

> P0-1/P0-2 是**纯增益**：不改语义、不加依赖，建议先做。
> P0-3 必须先在真实 graphene 包上确认 `source` 是对象且有 `state`（我们现有包是 precomputed，`source` 是字符串，测不出来）。

## 2.5 要**我们**决定的问题

这四项采集侧都能做，但要不要做取决于“复刻到什么程度”，得先定：

| 问题 | 现状 | 代价 |
|---|---|---|
| 像素回放只算 **canvas** 还是整个界面（侧栏/工具栏/通知/右键菜单）？ | 只拍 canvas（`canvas.toDataURL()`） | 整界面要换 `page.screenshot()` 或拼多个 canvas；体积大 2–3 倍，且面板位置需额外记 |
| 要不要记 **主题**（dark/light、OS 系统主题）？ | 不记 | 3 行；但只在“要复现非 canvas 区域”时才有意义 |
| 要不要记 **LOD 等级**（EM 瓦片分辨率）？ | 不记 | 需改 chunk manager（RF10 级别）；不记就只能像现在这样把像素降为参考指标 |
| 要不要记 **局部 panel 导航**（每个 pane 自己的位置/缩放）？ | 只记总 `position` | 同 P0-5；split view 才需要 |

> 我的建议：**只 canvas + 只主坐标**（现状）先做完，这四项等“真需要逐像素争议”时再上。
> 理由：像素作主线门已经被否决（[已定决策](已定决策.md) §8），额外记一堆省不了的代价不划算。
>
> **2026-10-29 用户拍板**：像素只算 canvas；**但工具/侧栏/通知的状态要记**；主题无所谓。
> 已落地为 `ui.state`（面板尺寸 + 工具栏 + 通知），主题和 LOD 仍不记。

## 2.7 已留好的采集口（已实现）

这四类东西已经**先留了口**，后续拿到实际获取方式时不用改架构，只注册一个函数：

### ① 任意私有状态 → `R.registerProvider(name, fn)`

```js
// 宿主侧（前端 hook / 油猴 / CDP 都行）
window.__caveRecorder.registerProvider('brush', function () {
  return { rev: s.revision, candidates: [...s.candidates].map(String) };
});
```

| 行为 | 已验证 |
|---|---|
| 有值就落 `ext.snapshot`（带 `provider`/`value`/`value_bytes`） | ✓ 3 条 |
| 值不变不重复发（200ms 调用 30 次 → 3 条） | ✓ |
| 抛错只报一次 `collector.status.provider_error`，30s 内不重试（不刷屏） | ✓ 1 条 |
| 没注册 = 零开销（不做任何事） | ✓ |
| `R.listProviders()` / `R.status().providers` 看得到次数与错误 | ✓ |

另：如果对方按 §3.1 暴露了 `window.__caveSnapshot`，**会自动挂上**，不用我们调。

### ② 组 Undo → `api.capability`

看到 URL 命中 `/undo/capabilities`、`/edit_groups`、`/capabilities` 就存**响应体**（最多 4000 字）。
“服务端到底有没有组撤销”只看这个，不看前端调用。已验证：假端点返回
`{"enabled":true,"grouped_undo":true,"version":1,"max_group_steps":8}` → 完整落盘。

### ③ 历史快照 → 版本指针已经在每一条里

采集侧能做的只有“把当时的版本指针钉住”：每条事件带 `t_wall`、`state_id`，提交事件带
`request_id`/`op_id`，选中集带 seg id。
**能不能按时间点查出当时的 Root/leaves/图像/Mesh，是后端能力**，前端和我们都决定不了。

### ④ 通知 → `ui.state.notices[]`

优先读 `[data-cave-notify]`（对方肯加就是结构化数据，带 `data-level`）；
退而读 `.neuroglancer-status-overlay` / `.neuroglancer-notification`；两个都没有就**不记**（不猜）。

## 3. 采不到（需要对方配合，P2）

> **下面每一项的落点都是 §2.7 的 `R.registerProvider(name, fn)`**——
> 不需要为每一项单独改 recorder，也不需要给它们各开一个事件名。

| # | 数据 | 为什么采不到 | 接入方式（按稳定性排序） | 代价/风险 |
|---|---|---|---|---|
| P2-1 | Brush/Trace/Fill/Eraser 的候选、邻接、笔迹（`SupervoxelSelectionSession`、`BrushStroke`） | 只在主线程内存，未进 state | ① 请前端暴露 `window.__caveSelection`（只读快照：candidates/adjacencies/revision）；② 我们 patch 原型方法（随构建变化）；③ DOM 观察（最脆弱，不推荐） | 中；①最稳，需要对方改 5–10 行 |
| P2-2 | 选区局部 Undo/Redo（`past/future`，最多 100） | 同上 | 同 P2-1，快照里带 `past_len/future_len` 与最近一次操作 | 低（搭 ① 的车） |
| P2-3 | `reviewedPlan / targetOverride / confirmed`（合并计划） | 同上 | 同 P2-1，快照里带 plan 摘要（目标 Root、批次数、是否确认） | 低 |
| P2-4 | 3D 预览集合（`previewSegments / selectionPreviewRoots`） | 同上 | 同 P2-1，只记集合大小与根 ID，不记渲染状态 | 低 |
| P2-5 | `ProofreadingEditState`（pendingGroup/pendingStep/progress） | 内存/响应，未落盘 | 同 P2-1；或从 P1-2 的请求头 + `api.ack` 推导 | 中 |
| P2-6 | 临时测量（`MeasurementState.results`） | 只在内存 | 同 P2-1，快照里带测量点与 scales | 低 |
| P2-7 | in-flight：`multicutState.blueGroup`、`multicutSubmissionPending`、`merge.inFlight`、`findPath.pending` | 只在内存 | 同 P2-1；或从请求开始/结束时间推断 | 低 |
| P2-8 | 通知/StatusTask 时间线 | DOM 生命周期 | MutationObserver 抓文本+时间（脆弱） | 中 |
| P2-9 | Chunk/GPU/加载状态 | Worker 内部 | 需要前端暴露或读诊断接口 | 高，不建议在我们这边做 |
| P2-10 | “取消/无修改离开” | 前端没有统一事件 | 我们用 `visibilitychange/beforeunload` + 输入静默近似（已有 gaps）；要精确需前端加事件 | 低（近似已够） |
| P2-11 | 组 Undo 的服务端语义（是否真撤销、部分成功） | 前后端协议不配套 | 属后端协议问题，需确认 `edit_groups` 路由与版本 | — |
| P2-12 | 历史快照（Root/leaves/图像/Mesh 按时点） | 前端未绑定历史资源 | **后端能力**，需确认保留期与查询方式 | — |

### 3.1 一次性能要到底的请求（可直接发给对方）

P2-1~P2-7 全部靠同一个入口。让他们在应用初始化后加一段**只读快照函数**：

```js
// 加到他们的 tool/session 初始化处（大约 10 行）
window.__caveSnapshot = () => ({
  rev: window.__caveSelection?.revision ?? null,
  candidates: [...(window.__caveSelection?.candidates ?? [])].map(String),
  adjacencies: window.__caveSelection?.adjacencies?.size ?? 0,
  pastLen: window.__caveSelection?.past?.length ?? 0,
  futureLen: window.__caveSelection?.future?.length ?? 0,
  plan: window.__caveMergePlan ? {
    targetRoot: String(window.__caveMergePlan.targetOverride ?? ''),
    batches: window.__caveMergePlan.batches?.length ?? 0,
    confirmed: !!window.__caveMergePlan.confirmed,
  } : null,
  preview: window.__cavePreview?.roots?.size ?? 0,
  measurement: window.__caveMeasurement?.results?.length ?? 0,
  pending: {
    blueGroup: !!window.__caveMulticut?.blueGroup,
    multicutSubmit: !!window.__caveMulticut?.submissionPending,
    merge: !!window.__caveMerge?.inFlight,
    findPath: !!window.__caveFindPath?.pending,
  },
});
```

我们这边只需要在 `sampleState()` 末尾加：

```js
if (typeof window.__caveSnapshot === 'function') {
  const s = window.__caveSnapshot();
  const sig = JSON.stringify(s);
  if (sig !== R.last.private) { R.last.private = sig; emit('private.snapshot', s); }
}
```

**这一步拿下 P2-1/2/3/4/6/7，一次 30 行。**

没有这个入口时，我们只能走 P2-1 的②（patch 原型）——每升级一次前端就可能静默失效，**不建议**。

**另外三样取决于后端/对方：**

| 项 | 要确认什么 |
|---|---|
| P2-11 组 Undo | 后端是否真有 `edit_groups` / `undo/capabilities` 路由；否则“撤销成功”只是前端乐观更新 |
| P2-12 历史快照 | 能否按时间点查出当时的 Root/leaves/图像/Mesh（决定“复刻”能不能做到历史时点） |
| P2-8 通知 | 是否愿意加 `data-cave-notify` 属性；不加就只能 MutationObserver 猜文本 |
