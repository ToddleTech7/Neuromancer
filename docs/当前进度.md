## 状态判定

| 标记 | 含义 | 判定标准（不满足就不许标） |
|---|---|---|
| `✅` | **已实现 + 已验证** | 有自动化脚本，能在本机跑绿，脚本里能指到项数 |
| `🟡` | **已实现，只验了一半** | 逻辑测过，但真实环境/真机未证；**必须写清差什么** |
| `🔵` | **已留口** | 接口在（能调、有测试），实际数据源没接 |
| `⬜` | **计划做** | 没开始，有明确触发条件（等什么才能做） |
| `❌` | **不做** | 已拍板，附理由与出处 |

> 规矩：`✅` 不许靠“我觉得能行”；`🟡` 不许含糊成“基本可用”——必须写缺什么。

| L1 工作段 / 多版本切分 | `⬜` | — | — | 暂缓（`已定决策`「主线是复刻」） |

**hover 口径（跟着产物走，`caveats` 字段里也有一份）**：

- `hover ≠ 注意`：指针压着人也可能在走神；只回答“压在哪个段上多久”，不推断“看了/判断了”；
- `viewer.focus` 是**变化才发**，停住不动没有新样本 → 时长算到“下一次变化”，最后一次标 `open_spans`；
- 短于采样点的划过会丢 → 次数与时长都是**下界**；
- `picked` 不像段 id 的（灰度值等）单独计数（`n_not_segment_id`），不混进结果；
- `status` 状态分类：`ok` / `no_picked`（有样本无值）/ `no_samples`——**“没人悬停”和“取不到值”必须分开**。
