# 使用说明

> 只讲"怎么做"。为什么这样做见 [设计说明](设计说明.md)；能力边界见 [功能清单](功能清单.md)。

## 先选场景

| 使用场景 | 入口 | 前置条件 |
|---|---|---|
| 项目在本机、有图形界面 | [本地（推荐）](#本地推荐) | Python 依赖 |
| 要采真实 CAVE 的页面 | [接入真实 CAVE](#接入真实-cave) | `--open` 或 `--cdp`，把 `--em/--seg` 换成你们的 |
| 验证安装与测试是否正常 | [只跑自检](#只跑自检) | Python 依赖 |

所有命令都在 `neuromancer/` 目录下执行。Python 用项目 venv 或系统 `python3`。

## 本地（推荐）

### 第一次试用：验证闭环

只有一处需要你动手：**在窗口里拖几下**。

```bash
# ① 依赖（一次性）
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt && python3 -m playwright install chromium

# ② 打开软件主页（点「开始采集」就在这页里做）
python3 scripts/nx.py
```

主页包含**开始 / 回放 / 看包 / 派生**，默认落在「开始」；工作台是白底浅色界面，
中间的 Neuroglancer 舞台保持黑底；鼠标红点按录制视口映射到当前 iframe，不会跑出回放区域，
录制时落在工具栏/侧栏的点会贴到边缘。

「开始」页从上到下：

| 项 | 说明 |
|---|---|
| 数据源 | 下拉选公开数据集（minnie65 BossDB / GCS 镜像）；选「自定义」时填 EM 与分割两个 URL |
| 保存到 | 留空 = 默认目录（显示在右侧）；点「浏览…」弹系统选目录，也可以手打路径 |
| 会话名 | 留空自动（`sess_日期_随机`）；填了就是目录名 |
| **开始采集** | 点它 → 新窗口打开 Neuroglancer 并开始录 |
| 已有会话 | 列出目录里的包（事件数/时长/帧数）；每行有「看轨迹 / 回放 / 改名 / 删除」|

录完 **先点窗口左下角「结束并保存」，再关窗口**；主页会自动刷出新会话。

「删除」现在先移到 `manual_sessions/_trash/`（可手动恢复）；真要永久删除需用 `pack_op("purge")` 或手动清空 `_trash`。

窗口里：按住左键拖几下、滚轮放大到看清细胞膜 → 点「打检查点」→ 再拖再打一次 →
点「结束并保存」→ 关掉窗口。

左下角面板默认收成快捷按钮条（打检查点 / 备注 / 结束并保存），避免挡住视野；
点标题栏的「▢」展开。展开后可拖动标题栏换位置、拖右下角调整大小，点「—」收回。
位置、大小和折叠状态记在浏览器本地，下次打开自动恢复。

**成功判据**（终端逐段打印）：

```
[PASS] 起点 position 已还原（唯一一次喂 state） — Δ=0.0 nm
[PASS] 段 session_start → manual_2：position 偏差 ≤ 60nm — Δ=0.0 nm
[PASS] 段末（manual_2）与当时关键帧像素收敛（rgb NCC ≥ 0.95）
RESULT: PASS
```

长会话建议用 `--start/--end` 按检查点分段；默认纯输入整段回放可能受 wheel 动画漂移影响，
`--reanchor-gesture` 提供可选的相机校正，报告中会标 `reanchored`。

打开 `<包>/replay/<时间戳>/` 里的 `rec_*.png` 与 `live_*.png` 并排比，
就是刚才看到的画面 vs 重放出来的画面。

`[SKIP]` 不计分：`pixel_unstable`（分割层没加载完）、`color_mismatch`（亮度对、配色不同）。

### 采集流程

```bash
bash scripts/demo_manual.sh --open
```

它会：

1. 起一个本地 Neuroglancer，加载公开 minnie65（EM + 分割）；
2. **自动开一个浏览器窗口**，并在 document-start 时把采集器注入好；
3. 打印 `VIEWER_URL` 与保存目录。

> 终端第一行 `[python] …` 是它选中的解释器：**第一个能 import `neuroglancer` +
> `playwright` 的那个**（`$PYTHON` → `.venv` → `venv` → 上一级旧 venv → `python3`）。
> 空 venv 不会被选中；全都没有时直接打印安装命令。
>
> 窗口有没有界面：macOS / Windows 默认**有界面**；Linux 看 `DISPLAY` / `WAYLAND_DISPLAY`。
> 想强制无头（只做注入自检）：`CAVE_HEADLESS=1 bash scripts/demo_manual.sh --open`。
> 报 `Executable doesn't exist … ms-playwright/chromium-…` = 那个解释器没装浏览器，
> 跑它的 `-m playwright install chromium` 即可（换解释器后要重装）。

**会话名（目录名）可以自定义**：

```bash
python3 scripts/nx.py collect --session-name 小鼠皮层_第3轮
# → results/manual_sessions/sess_小鼠皮层_第3轮/
```

不给就用自动名 `sess_<UTC 时间戳>_<5 位随机>`。中文保留；空白换成 `_`；
`/ \ : * ? " < > | #` 换成 `_`；**不同会话同名不覆盖**（自动加 `__<时间戳>` 后缀），同一 `session_id` 重存会覆盖该目录。
完整规则见 [../results/README.md](../results/README.md) 的「会话名怎么定」。

窗口里你正常操作即可。左下角面板：

| 按钮 | 作用 |
|---|---|
| 打检查点 | 记一个锚点，并顺手拍一张带 state 绑定的关键帧（回放时比对用） |
| 备注 | 写一句人工判断，绑定当前视角（落 `notes.jsonl` + `note` 事件） |
| 结束并保存 | 收尾并落盘到 `results/manual_sessions/<session_id>/` |

> `cave_recorder.user.js` 自己也带一个「CAVE Recorder」面板（开始/停止/截图/导出），
> 已经由 `manual_boot.js` 隐掉（`#cave-recorder-panel` 仅保留 `display:none`）——
> 两套按钮并存时，「停止」会截断会话、「开始」会清空已记事件，误点代价太大。
> 它的按钮也只走 `data-cave-ui` 白名单（不进输入流），不信可看 DOM 属性。

在**换位置前、缩放后、看完一处时**按需要打检查点。
点面板本身不会进入输入流，不会污染回放。

**怎么退出**：点完「结束并保存」，直接**关掉那个浏览器窗口**——服务随之退出，包已经落盘。
（没有图形界面时，脚本只做注入自检，20 秒后自动退出，不留后台进程。）

### 采集设置（面板「设置」）

左下角面板点「设置」可以改，改完写 `localStorage`，下次打开自动生效：

| 项 | 选项 | 说明 |
|---|---|---|
| 移动采样 | 全量 / 50 / 100 / 200 / 600 ms | 默认全量（回放要完整输入流）；采样会让拖动被抽稀 |
| 状态轮询 | 只靠订阅 / 200 / 600 / 1000 / 2000 ms | 兜底采样；设 0 则完全依赖订阅 |
| 选中集/图层变化即时记 | 开 / 关 | 订阅 `state.changed`，去抖 100ms；关了就只靠轮询 |
| 每个检查点拍照 | 开 / 关 | 打开后回放才有像素可比（一小时约 120 MB） |
| 语义关键帧 | 开 / 关 | 缩放跨档/图层/选中各拍一张，停住拍一张 |
| 停留 | 关 / 3 / 5 / 10 s | 中心+选中+可见层不变超过这么久就拍一张 |
| 事件上限 | 2 万 / 5 万 / 20 万 / 50 万 | 超了记 `overflow` 并在 `inspect_pack` 告警 |

默认是**精度优先**：全量移动 + 200ms 状态轮询 + 50ms 订阅去抖 + 语义关键帧开 +
停留 5s。占用取决于操作密度：**每张图约 0.6 MB**，按每分钟 3–10 张语义图估算
约 100–400 MB/小时；只要行为不要图时，关掉「每个检查点拍照」和「语义关键帧」
即可回到 ~15 MB/小时。

也可以不改界面，直接用 URL 参数临时覆盖（优先级最高）：
`?cave_move_ms=0&cave_state_ms=200`。

**注意**：订阅和轮询至少要留一个；两个都关会拒绝保存（否则状态完全记不到）。

### 回放

```bash
bash scripts/demo_manual.sh --replay
```

做的事：新开一个页面 → 只恢复**起点**的 state → 之后**只喂输入事件** →
每到一个检查点就比一次站姿，段末再比一次像素。

通过标准：

```
每段 position Δ ≤ 60 nm   （≈15 体素 @4nm）
段末 rgb NCC ≥ 0.95       （闭环等瓦片，最多 12 次）
默认按实际面板分区报告：4panel 的 2D 面板各算一块，左下 3D 单列；
开关面板后分区数量跟着变，`--compare-all` 才把 3D 也纳入。
```

### 数据存到哪、怎么改

缺省落点是仓库内的 `results/manual_sessions/<会话名>/`，会话名缺省是
`sess_<ISO时间>_<5位随机>`。修改方式：

| 修改目标 | 命令 | 作用范围 |
|---|---|---|
| 只改这一次的名字 | `nx.py collect --session-name 小鼠皮层_第3轮` | 目录名（中文保留；不同会话同名加后缀） |
| 只改这一次的位置 | `nx.py collect --out ~/neuro_data` | 这一次；`nx` 默认还找老地方 |
| 一劳永逸改位置 | `export NM_SESSIONS=~/neuro_data` | collect 写到那，studio / pack / replay 也从那找 |

`NM_SESSIONS` 建议写进 shell 配置（`~/.zshrc`）。不设就一直是仓库内 `results/`。

### 查看会话（双击就能看）

每个包根目录都有 `打开.html`，**双击**就在浏览器打开：

- 左上角：会话 ID、时长、页面 URL、事件计数
- 中间：视角轨迹（position 的 x-y 俯视）
- 下面：全部事件的时间线表格（大量事件也能滚动查看）
- 有 join 结果时，服务端 op 行会按时间插入

自包含单文件，不联网、不依赖服务。要更细的界面级回放，使用 `nx.py` 的工作台。

### 查看会话包（内容与可回放性）

```bash
python3 scripts/inspect_pack.py                 # 最新一个会话包
python3 scripts/inspect_pack.py <包目录> --json  # 给脚本用
```

它只读，打印：事件构成、能用的锚点（带 `position` 的 checkpoint）、被丢弃的锚点、
每张关键帧的状态（`captured` 才能比像素）、包健康度与 integrity。
字段含义见 [数据格式](数据格式.md)。

### 崩溃/误关之后：从草稿恢复

采集器每 30 秒把“新事件”增量发到 `POST /draft`，落在
`results/manual_sessions/_draft_<session>/`。即使没点保存就关了浏览器/进程崩了，
最多丢最后 30 秒：

```bash
python3 scripts/nx.py recover --list   # 看有哪些草稿
python3 scripts/nx.py recover          # 把最新草稿转成正式包
```

图也是**增量**传的（一次最多 8 张，按 `shot_id` 去重），所以恢复出来的包**图也在**；
只有最后 30 秒内拍的那几张可能丢。正式保存成功后，同 session 的草稿会被自动删掉。

### 产物在哪

```text
results/manual_sessions/<session_id>/
  manifest.json              配置（采样粒度/关键帧规则）、health、integrity
  client/events.jsonl        事件流，一行一条
  client/shots/shot_N.png    关键帧（painted_partial 的也留档）
  client/shots/shots.jsonl   关键帧索引（capture_status / state_sha / content）
  client/notes.jsonl         备注（如果写过）

<包>/replay/<ts>/
  report.json                逐段 Δpos / rgb / attempts / pixel_unstable
  rec_<锚点>.png             录制时那一帧
  live_<锚点>.png            回放时同一时刻
  final.png                  回放结束的整页截图
  replay.webm                整段回放的录屏（只有加 --video 才有）
```

看 `rec_*` 与 `live_*` 并排，就是"复刻像不像"的最直接证据；`replay.webm` 是整段
过程的录屏（由回放端录制）：

```bash
python3 scripts/replay_manual_session.py \
    --pack results/manual_sessions/<id> --video     # → <ts>/replay.webm
open <包>/replay/<ts>/replay.webm                    # 或直接 open 那个目录
```

### 界面级回放（可拖时间轴）

```bash
python3 scripts/nx.py                 # 最新包（等价于 nx.py studio）
python3 scripts/nx.py studio <包>     # 指定包
```

打开的是**真 Neuroglancer 页面** + 一条时间轴。

**一个窗口里切换功能（顶部 tab）**：

| tab | 做什么 | 什么时候用 |
|---|---|---|
| **回放**（默认） | 拖时间轴 / 空格播放 / 点备注跳转 / 侧栏看“这一刻” | 想“回到当时看一眼” |
| **看包** | 卡片显示事件数/时长/完整 state/可用关键帧/体积/integrity；下面列事件构成、锚点、完整性告警 | 录完先确认“这段记全了没” |
| **派生** | 两个按钮：切段（`cave_episodes`）/ 关联 op log（`cave_join`）；输出直接显示在页面上 | 想拿“一段一段的行为”或对服务端 op log |

看包和派生 tab **不重写逻辑**：看包调 `inspect_pack.summarize()`，派生直接 `subprocess` 跑
现成的命令行脚本——所以页面上看到的和命令行跑出来的一模一样。

**顶栏先选“打开什么”**：

| 控件 | 选择范围 |
|---|---|
| 回放包 | `results/manual_sessions` 最近 30 个（按修改时间倒序），选完点「打开」 |
| 数据源 | `跟随回放包`（默认，用包里录到的 source）/ `minnie65 · BossDB` / `minnie65 · GCS 镜像` / `自定义 URL` |

选 `自定义 URL` 时，右侧会出现两个输入框（EM 与分割，都要填 `precomputed://…`）；
若想常驻一份“我们自己的数据”，启动时设环境变量即可多一条选项：

```bash
NEURO_EM_URL=precomputed://… NEURO_SEG_URL=precomputed://… python3 scripts/nx.py
```

切数据源会重建图层并**钉住**（之后再拖时间轴不会被包里的 source 改回去）；
切回“跟随回放包”即恢复。

**其余控件**：

- 拖时间轴 → 跳到最近的一份完整 state 快照（平均 2.4 s 一个），秒级响应；
- 右侧实时显示这一刻的数据层：位置 / 缩放 / 布局 / 选中集（几个 id）/ 快照号；
- 时间轴上的黄色刻度是关键帧、蓝色是备注；**点右侧备注会跳过去**，
  「上一/下一检查点」逐点跳；
- 附近有关键帧时，右栏直接显示当时那张图（`captured` / `painted_partial`）；
- 空格播放，`1x/2x/4x/8x` 可选，←/→ 一次 1 秒；
- **「精确重放到这里」**：新开一个窗口（Playwright），从上一个检查点开始逐条重放输入，
  到当前时间轴位置就停——补上快照之间看不到的连续过程；
- **「导出这一段视频」**：同样从上一个检查点重放到此处，录成
  `<包>/replay/<ts>/replay.webm`，面板会显示完成路径。
- **「采集新会话」**（顶栏）：直接开采集窗口（等同 `nx.py collect`）；
  关窗后顶栏显示「新包：sess_… 载入」，点一下就能在这个工作台里看刚采的那段。

边界：拖动本身是**跳快照**；要看连续过程用上面两个按钮，或用 `nx.py replay`。
像素清晰度（瓦片 LOD）可能与录制端不同，不承诺逐像素一致。

### 统一入口 `nx.py`

| 命令 | 作用 |
|---|---|
| `python3 scripts/nx.py` | 回放工作台（默认） |
| `python3 scripts/nx.py collect` | 采集窗口（原 `demo_manual.sh --open`） |
| `python3 scripts/nx.py replay` | 逐条输入重放 + 逐段比对 |
| `python3 scripts/nx.py export --seek-t 140` | 重放到 140 s 并录成视频 |
| `python3 scripts/nx.py pack` | 包里存了什么（只读） |
| `python3 scripts/nx.py verify-pack` | 校验包完整性（事件/索引/PNG 哈希） |
| `python3 scripts/nx.py doctor` | 环境自检（依赖/浏览器/目录/端口） |
| `python3 scripts/nx.py export-csv` | 导出 `derived/csv/events.csv` / `episodes.csv` / `hover.csv` |

后续参数都**原样透传**给下层脚本，旧用法仍可用，
例如 `nx.py replay --pack <包> --start manual_2 --end manual_3 --mesh-wait 30`。

## 远程服务器

页面在服务器上、你用自己电脑的浏览器。可选择调试端口或控制台粘贴。

### 调试端口（带参数启动 Chrome）

```bash
# 服务器上
bash scripts/demo_manual.sh --cdp        # 会打印完整命令
# 你电脑上
google-chrome --remote-debugging-port=9222 --user-data-dir=/tmp/cave-profile
ssh -R 9222:127.0.0.1:9222 -L <ngport>:127.0.0.1:<ngport> -L 8899:127.0.0.1:8899 <user>@<host>
# 然后在那个 Chrome 里打开数据页：服务端会自动注入并刷新一次
```

实测：注入后 `window.__caveGLPatched === true`、面板出现「录制中」。
代价是每次都要带参数启动并建立隧道，所以给校对员仍推荐本地采集。

### 控制台粘贴（最轻，没有像素）

`/install` 页面底部有「复制控制台脚本」，然后数据页 `F12 → Console → 粘贴 → 回车`
（Chrome 可能要先输入 `allow pasting`）。

- 能录：pointer / wheel / key / state / gesture / 备注；
- 缺关键帧（补丁太晚，图是黑的）→ 回放跳过像素比对，只验位置/尺度。

## 接入真实 CAVE

分两种情况：只有数据（EM/分割的 URL），或者已经有一个 NG 页面链接。

### 准备接入信息

无论哪种方式，回放要能重建同一幅画面，就需要：

| 项 | 形式 | 例子（占位） |
|---|---|---|
| EM 图像源 | `precomputed://…` | `precomputed://https://<store>/<dataset>/em` |
| 分割源 | `precomputed://…` 或 `graphene://…` | `precomputed://https://<store>/<dataset>/seg` |
| 体素尺寸 dims | 三个数（nm） | `4 4 40` |
| 初始位置 | 三个数（voxel） | `190587 114102 21773` |

**确认只读访问**：浏览器直接打开 `<em>/info` 和 `<seg>/info` 能看到 JSON，
且无需签名/Cookie，就说明采集器能读。

### 采集端：把默认数据源换成你们的

```bash
python3 scripts/cave_manual_server.py --open \
    --em  precomputed://https://<store>/<dataset>/em \
    --seg precomputed://https://<store>/<dataset>/seg \
    --dims 4 4 40 --pos 190587 114102 21773
# 不想每次敲：直接改 cave_manual_server.py 顶部的 EM_DEFAULT / SEG_DEFAULT / A_DEFAULT
```

### 已经有一个 NG 页面链接（`https://<ng-host>/v/<token>/`）

**直开（推荐，已实测）**：

```bash
python3 scripts/cave_manual_server.py --url https://<ng-host>/v/<token>/ --open
# 站点需要登录态时，复用你自己浏览器的用户目录：
```

前提：目标页面是**标准 NG**（顶层 `window.viewer` 存在）。若是包装页 / NG 在

一个前提：**回放机要能访问同一份数据**，否则只能比位置/尺度，图是空的。

### 回放端：让回放看同一份数据

| 做法 | 命令/操作 | 适用 |
|---|---|---|
| 跟随包（默认） | 工作台数据源选「跟随回放包」 | 包里记的就是你们的源 |
| 临时指定 | 工作台数据源选「自定义 URL」填 EM/分割 | 临时换一份数据看 |
| 常驻一份 | `NEURO_EM_URL=… NEURO_SEG_URL=… python3 scripts/nx.py` | 团队固定环境 |
| 逐条比对 | `nx.py replay --pack <包>`（跟随包里的源） | 需要跑验收 |

### 接入前检查

1. `/<em>/info` 与 `/<seg>/info` 能匿名读（只读即可，不需要写权限）；
2. dims 与数据一致（错了位置会整体偏）；
3. 分割是 `precomputed` 还是 `graphene`（后者要带 `graphene://` 前缀）；
4. 回放机网络能到同一个存储（否则画面空白、只有十字）。

## 故障排查

| 症状 | 原因 | 处理 |
|---|---|---|
| 面板不出现 | 注入没生效 | 看 `window.__caveRecorder` / `window.__caveGLPatched` 是否为真 |
| 左下角面板只显示一半 | 视口比屏幕可视区高，`fixed; bottom` 的按钮被窗口下边裁掉 | `CAVE_WINDOW_SIZE=1280,700 bash scripts/demo_manual.sh --open`（默认 1280×740） |
| 关键帧全黑（`blank_readback`） | 补丁时机太晚 | 用 `--open` / `--cdp`（控制台版补丁时机晚） |
| 回放 Δ 很大（几百 nm） | 视口不一致 | 脚本已按包内 `viewport.css_px` 建同尺寸视口；改过就别手改 |
| 回放位置对、画面不同 | 数据源不同或分割层没加载完 | 确认两边数据源一致；`pixel_unstable` 不计分 |
| 保存失败 | 8899 不可达 / 服务已停 | 检查隧道与服务进程 |
| 一直停在“正在保存…” | **端口被别的程序占了**（绑得上不代表收得到：127.0.0.1 上更具体的监听会抢走请求） | 看终端有没有 `[port] 8899 已被占用…改用 89xx`；保存请求 20s 超时会自己报错，不会永远挂着 |
| 点「备注」窗口一闪就没 | `window.prompt` 被宿主默认 dismiss（Playwright 就是如此） | 已改成页内输入框（回车记下 / Esc 取消），不再用 prompt |
| 报告里 `pixel_unstable` | 回放端彩色占比与录制差 >0.2 | 不计分；看 `rec_*` / `live_*` 判断是加载中还是真的不一致 |
| 报告里 `painted_partial` | 拍的那帧还没画完 | 采集时就标了，不进保真度均值 |
| `motion_lag` | 拖动中拍的帧 | 与快门 state 差一帧，不算回放错 |

## 常用参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--em` / `--seg` | 公开 minnie65 | 数据源（`precomputed://https://...`） |
| `--pos` | `190587 114102 21773` | 起始位置（体素坐标） |
| `--dims` | `4 4 40` | 体素尺寸（nm），必须与数据一致 |
| `--port` | `8899` | 保存端点端口 |
| `--open` / `--cdp` / `--replay` | — | 本地直开 / 调试端口注入 / 回放最新包 |
| `--video` | 关 | 回放时给 `replay_manual_session.py` 加：把**整段过程**录成 `<out>/replay.webm`（校验仍是端点制，只是多了个能看的产物） |
| `--headed` | 关 | 回放时开窗口给你看着重放（不录屏时用这个） |
| `--anchor <名称>` | — | 直接恢复到某个检查点的视角（**不重放输入**）：`bash scripts/demo_manual.sh --open --anchor manual_3`；不带 `--pack` 用最新包，列位置在输出 `[anchor] …` 行 |
| `--mesh-wait <秒>` | `0` | 段末恢复选中集后额外等待（等 3D mesh 画出）。3D 面板要上镜就 `--mesh-wait 30`（实测同一视角 ~35 s 才出 mesh） |
| `--start` / `--end` | — | 只回放某一段：`--start manual_2 --end manual_3`。**推荐分段跑**：一段一次，稳定且便于定位 |

回放端另一个开关（环境变量）：`CAVE_MESH_SCALE=0` 关掉 3D mesh 渲染后跑
——有选中段时 NG 会去拉 mesh 分片，页面一忙，输入重放会明显变慢。

改默认值：改 `scripts/cave_manual_server.py` 顶部常量。
