# 后端接入与缺口补齐

> 面向：后端负责人、CAVE 前端负责人、NG fork 维护者、采集/回放开发。
> 目的：说清“现在已经能做什么、还缺什么、每一项由谁补、补完怎么验收”。
> 接口是建议契约，不是现有实现；后端可以按自己的路由风格调整，但字段语义要保留。

## 结论先行

采集端已经能独立完成：输入、viewer state、选中集、图层、关键帧、备注、会话包、输入回放和状态回放。

现在缺的**不是更多浏览器端采集逻辑**，而是服务端能力：

1. **操作日志与提交回执**：把一次前端提交和一次服务端 operation 精确对上，并能按 `client_request_id` 反查。
2. **版本化读取**：按录制时刻读回当时的 Root、分割、EM、mesh，而不是读最新版。
3. **只读回放数据源**：回放期间服务端拒绝写，不二次修改线上数据。
4. **局部资产导出与治理**：按 operation 导出前后 mask/EM，并定义权限、保留期和审计。

另外还有不属于后端的部分：

- **NG fork / 前端 hook**：当前工具、草稿、action ID、真实加载态（`V_loaded`）；
- **本工具客户端**：把收到的字段落盘、派生、回放和验证。

## 当前能力边界

| 层 | 已经能做 | 仍然缺 |
|---|---|---|
| 浏览器采集 | 只读记录输入、完整 state、选中集、图层、关键帧、备注、草稿 | 工具内部状态、V_loaded、私有候选/笔迹 |
| 会话包 | 目录契约、SHA256、草稿恢复、完整性校验 | 服务端权威 operation 关联 |
| 回放 | 输入级回放、state 级回放、工作台、分段回放 | 按历史版本重建、只读回放源 |
| 派生 | 归一化、片段切分、no-op、悬停统计 | 与真实 op log 的一对一 join |
| 导出 | 事件/片段/悬停 CSV、样本卡 | 编辑前后 ROI mask/EM 的异步打包 |

## 后端接口需求

### 操作日志与提交回执

这是第一优先级。没有它，join 只能靠时间窗和 Root 兜底，样本里的 `process.session_id` 只能标 `simulated`。

**需要的查询**

```http
GET /api/oplog?from=<iso>&to=<iso>&root_id=<id>&session_id=<id>&cursor=<c>
Authorization: Bearer <token>
```

返回：

```json
{
  "operations": [
    {
      "operation_id": "1956846",
      "server_sequence": 12345,
      "operation_type": "merge",
      "operation_timestamp": "2026-10-30T12:00:00.123Z",
      "before_root_ids": ["864691135417393594"],
      "after_root_ids": ["864691135417393595"],
      "source_coords": [[190587, 114102, 21773]],
      "sink_coords": [[190600, 114110, 21773]],
      "user_id": "u-123",
      "session_id": "s-456",
      "client_request_id": "req-abc",
      "request_outcome": "committed",
      "attempt_n": 1
    }
  ],
  "next_cursor": "…"
}
```

**按客户端请求反查**

```http
GET /api/operations/by-request?client_request_id=req-abc
```

返回该请求的尝试链和最终状态：

```json
{
  "client_request_id": "req-abc",
  "attempts": [
    {"attempt_n": 1, "outcome": "timeout", "server_time": "…"},
    {"attempt_n": 2, "outcome": "committed", "operation_id": "1956846", "server_time": "…"}
  ],
  "final_operation_id": "1956846"
}
```

**语义要求**

- `client_request_id` 由客户端生成，重试时保持不变；服务端按它做幂等。
- `operation_id` 只对应真正执行的一次操作；超时重试不能产生第二个 operation。
- `before_root_ids` / `after_root_ids` 是该操作实际修改的 Root，不是提交前的页面选中集。
- `source_coords` / `sink_coords` 是服务端权威坐标；前端点击坐标只能作参考。
- `request_outcome` 至少区分：`committed`、`rejected`、`failed`、`cancelled`、`timeout`、`unknown`。
- 支持分页、时间窗和按 Root 查询；不要要求客户端先拉全量。
- 返回 `server_time`，用于校准客户端墙钟，不要只给客户端本地时间。

**验收**

- 人为制造 502/超时，客户端重试后服务端只执行一次。
- 按 `client_request_id` 能查到唯一 `final_operation_id`。
- 连续两次编辑同一 Root，`before/after` 链闭合。
- `verify_cave_join.py` 能从 `simulated` 升级为真实 `exact-anchor`。

### 版本化读取与只读回放

没有这组能力，回放只能证明“画面像”，不能证明“是当时那个版本”。

**版本解析**

```http
GET /api/versions/{root_id}?at=<iso>&include=segmentation,em,mesh
```

返回：

```json
{
  "root_id": "864691135417393594",
  "version": "2026-10-30T11:59:58Z",
  "segmentation_uri": "graphene://…@<version>",
  "em_uri": "precomputed://…@<version>",
  "mesh_uri": "precomputed://…@<version>",
  "resolution_nm": [4, 4, 40],
  "readonly": true,
  "expires_at": "2026-11-30T00:00:00Z"
}
```

**只读回放源**

```http
POST /api/replay-sources
```

请求：`{root_ids, at, layers}`；返回可直接给 Neuroglancer 的只读 URI 与过期时间。
服务端必须拒绝该凭据下的写请求，并在审计里记录“回放读”。

**资产解析失败**

```http
GET /api/replay-assets/resolve?root_id=…&at=…&kind=segmentation
```

失败也要返回结构化结果，不能静默换最新版：

```json
{"status": "expired", "reason": "retention window passed", "fallback": null}
```

`status` 至少覆盖：`ok`、`expired`、`revoked`、`missing`、`not_ready`。

**验收**

- 另一个账号在录制后继续 merge/split，回放仍读录制时版本。
- 过期/撤权/丢失各造一例，返回 `status + reason`，不返回最新文件。
- 回放期间服务端审计日志零写调用。
- `replay_manual_session` / `verify_replay_fidelity` 能绑定到版本 URI。

### 提交链路与撤销

如果服务端已有写接口，需要补齐可观测性；没有写接口时，这一组可以后置。

需要的能力：

- 提交请求带 `client_request_id`，重试幂等；
- 返回 `operation_id`、`request_outcome`、`attempt_n`；
- 支持 `undo_of_operation_id`，能区分“前端取消”“服务端拒绝”“已提交后 undo”；
- 组 Undo 能力可通过 `GET /api/capabilities` 暴露：`{grouped_undo, max_group_steps, undo_scope}`；
- 错误返回稳定的 `error_type`，不要把 HTML 错误页直接给客户端。

**验收**

- 一次 merge 的 `edit.request` 与 `operation_id` 对上。
- 前端取消不产生服务端 operation。
- 提交失败重试只执行一次。
- undo 能指向被撤销的 operation。

### 局部资产导出

训练/复核需要“这次编辑前后同一 ROI 的 mask/EM”，不建议在编辑请求里同步做。

```http
POST /api/roi-exports
```

请求：`{operation_id, root_ids, bbox, include: ["segmentation_before","segmentation_after","em"]}`

返回：

```json
{"job_id": "roi-123", "status": "queued"}
```

查询：

```http
GET /api/roi-exports/{job_id}
```

返回 `status`、`progress`、`output_manifest`、`checksum`、`expires_at`。

**验收**

- 两份 mask 可直接比较，SHA256 可校验，manifest 带 `operation_id`。
- 大 ROI 导出不阻塞编辑接口。
- 失败任务有明确 `status + reason`，不生成半成品。

### 治理与安全

上线前需要明确：

- 认证方式、CORS 白名单、允许的本地回调地址；
- 只读 token 与读写 token 分离；
- 不把 token、Cookie、Authorization 头写进会话包；
- 截图/EM 可能含未公开数据，定义保留期、访问范围、删除方式；
- 按用户/会话限速，避免回放或导出拖垮编辑接口；
- 审计：谁在什么时间读了哪个版本、导出了哪个 ROI；
- 匿名化：会话包里的 user/session 标识可配置脱敏。

## NG fork / 前端 hook 需求

这些不是后端接口，但同样阻塞“所有功能补齐”。

### 当前工具、草稿与 action

在编辑工具 handler / action dispatcher 处发只读事件：

```text
tool_select {tool_id}
draft_update {tool_id, sources, sinks, preview}
action_start {action_id, args}
action_end {action_id, result}
```

验收：一次 Split 的草稿 sources/sinks、预览形状与服务端最终结果一致；前端 `action_id` 与服务端 `operation_id` 能对上。

### V_loaded 真实加载态

在 chunk manager 的加载/失败回调发：

```text
chunk_loaded {chunk_id, mip, source_version, ms, ok}
chunk_failed {chunk_id, mip, source_version, reason}
```

验收：断网时失败 chunk 出现在事件流；恢复网络后能看到补拉；回放能区分“当时没画完”和“输入回放错”。

### 私有候选/笔迹快照

前端加一个只读函数即可，不需要为每项单独改 recorder：

```js
window.__caveSnapshot = () => ({
  revision: window.__caveSelection?.revision ?? null,
  candidates: [...(window.__caveSelection?.candidates ?? [])].map(String),
  pastLen: window.__caveSelection?.past?.length ?? 0,
  futureLen: window.__caveSelection?.future?.length ?? 0,
  plan: window.__caveMergePlan ? {
    targetRoot: String(window.__caveMergePlan.targetOverride ?? ''),
    batches: window.__caveMergePlan.batches?.length ?? 0,
    confirmed: !!window.__caveMergePlan.confirmed
  } : null,
  pending: {
    multicut: !!window.__caveMulticut?.submissionPending,
    merge: !!window.__caveMerge?.inFlight
  }
});
```

recorder 在 `sampleState()` 末尾读取该函数，变化时发 `private.snapshot`；没注册则零开销。一次接入可覆盖候选、局部 Undo、合并计划、3D 预览、测量、in-flight 状态。

## 建议实施顺序

```text
阶段 0（现在）
  纯客户端采集/回放；所有真实后端字段标 simulated/unknown。

阶段 1：能 join
  op log 查询 + client_request_id 反查 + 服务端时间。
  验收：exact-anchor；连续编辑 before/after 链闭合。

阶段 2：能按版本回放
  版本解析 + 只读回放源 + 资产解析失败语义。
  验收：旧时间点回放不串版本；审计零写。

阶段 3：能证明提交
  提交回执 + 幂等重试 + undo/取消区分。
  验收：超时重试只执行一次；取消不产生 operation。

阶段 4：能采工具内部
  NG fork 的 tool/draft/action/V_loaded + 前端 __caveSnapshot。
  验收：Split 草稿与结果一致；断网 chunk 失败可查。

阶段 5：能导出与治理
  ROI 异步导出 + 权限/配额/审计/保留期。
  验收：mask SHA256 可校验；越权与超限被拒。
```

### 如果只能先做最小集

先做最小集：

1. **op log 按时间/Root 查询**；
2. **`client_request_id` 反查 `operation_id`**；
3. **按录制时刻解析只读数据源**。

完成后，`cave_join`、真人回放和状态回放都能从“近似”升级为“可审计”。

## 联调验收矩阵

| 能力 | 命令/产物 | 通过标准 |
|---|---|---|
| 真实 op log join | `verify_cave_join.py` | 出现 `exact-anchor`，不再只有 `anchor-estimated` |
| 超时重试幂等 | 人为 502 + 重试 | 服务端仅一次 operation，`by-request` 可查 |
| 版本化回放 | `replay_manual_session.py` / `verify_replay_fidelity.py` | 读旧版本；换版本后画面/归属变化可解释 |
| 只读回放 | 审计日志 | 回放期间零生产写 |
| 历史资产解析 | `curl` 过期/撤权/丢失 | `status + reason`，不返回最新文件 |
| 工具/草稿 | NG fork 日志 | Split 草稿、预览、最终 operation 一致 |
| V_loaded | 断网/弱网 | 失败 chunk 出现在事件流；恢复后补拉可见 |
| ROI 导出 | `POST/GET roi-exports` | 前后 mask、SHA256、operation_id 齐全 |
| 治理 | 跨用户/超限/保留期 | 越权拒绝、限速生效、无 token 落盘 |

## 不属于后端接口的决策项

这些缺口不是接口问题，先定规则再写代码；不要在联调时临时猜：

- L1 工作段/多版本切分：采集只负责记录，切分是派生层策略；
- PP08/PP09 语义标签、D15 no-op 分类：需要产品定义，不能当后端字段；
- 采样阈值、关键帧阈值：属于客户端和派生层，后端不决定；
- 截图/EM 的保留期和访问范围：属于治理，先于接口确定；
- 是否把像素一致当主线门：已降为参考指标，不要求后端或 NG 为它改协议。

## 不要向后端要的东西

这些不是后端责任，或者已经明确不做：

| 项 | 原因 | 应由谁做 |
|---|---|---|
| tile / chunk / mip 内部队列 | 真状态在 Worker；像素已降为参考指标 | NG fork；本工具不采 |
| 逐像素一致 | LOD/瓦片加载时序不可控 | 不作为主线门 |
| 主题 dark/light | 用户已拍板不重要 | 不采 |
| 采样阈值/切分规则 | 属于客户端和派生层策略 | 本工具 |
| 把截图/EM 默认上传到服务端 | 可能含未公开数据 | 先定义治理，默认本地 |

## 给后端的最小问题清单

联调前请先回答：

1. op log 能否按时间窗、Root、`client_request_id` 查询？保留多久？
2. 提交请求是否已有幂等键？没有的话能否加 `client_request_id`？
3. 是否能按时间点返回 Root 的 segmentation/EM/mesh 版本？过期后返回什么？
4. 是否有只读回放凭据/接口？能否保证拒绝写？
5. 历史资产解析失败有哪些状态？是否会静默回退最新版？
6. 认证、CORS、本地回调地址、限流怎么做？
7. ROI 导出是否允许异步任务？输出 manifest 能否带 operation_id 和 checksum？
8. 截图/EM 的保留期、访问范围、删除方式是什么？

## 交接定义

后端交付一项能力时，同时给：

- 可调用的测试环境地址；
- 认证方式和测试账号（不要给生产 token）；
- 一份真实响应样例（脱敏）；
- 失败状态样例；
- 一份验收命令或 curl；
- 字段语义说明，尤其是时间、Root、版本、operation 的对应关系。

本工具侧收到后，更新 `capabilities()`、`当前进度`、`数据格式`，并把对应的 `simulated`/`unknown` 改成真实来源。未拿到真实响应前，不把接口写成“已接通”。
