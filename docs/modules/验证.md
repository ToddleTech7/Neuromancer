# 模块：验证（每个数字从哪来）

更新：2026-10-26 · 数字汇总在 [文档地图](../目录.md#当前验证数字)，本页讲**每道检查守什么、失败说明什么**。

## 职责

用可重跑的检查代替"看起来对"，并让失败可解释：**每条断言对应一个具体退化方式**。
**不做**：不测界面美观、不测性能、不用"跑通一次"代表"一直对"。

## 设计要点（写断言时守住）

1. **一条断言 = 一个退化方式**。写不出"失败意味着什么"的断言，不要加。
2. **缺输入就 `skip` 并说明原因**，不计入 PASS；例如没开 `cave_kf` 时保真度直接报"没有配对"。
3. **阈值要留机器抖动余量**：NCC 用 0.90/0.80 而不是 0.98，因为瓦片加载有秒级抖动。
4. **失败必须红**：demo 里保真度是 PASS 条件，`--no-fidelity` 时那三条断言不参与计数（不假装跑过）。
5. **数字只写在两处**：文档地图 + 开发日志；脚本内部不要再复制一份"上次是 24/24"。

## 怎么跑

```bash
# 日常一条命令（离线，~30 秒）：单测 + join + 提交钩子
bash scripts/check_offline.sh
bash scripts/check_offline.sh --quick      # 只跑单测（1~2 秒）

# 改动采集器后（需外网）
python3 scripts/verify_cave_recorder_e2e.py
python3 scripts/demo_capture_episodes.py          # 含回放保真度

# 改动 join / 包 / 派生后
python3 scripts/verify_cave_join.py
python3 scripts/cave_episodes.py <会话包>

# 改动工作台后（需浏览器）
python3 scripts/verify_ui_and_providers.py
```

## 已知薄弱处（不掩饰）

| 薄弱点 | 影响 | 现状 |
|---|---|---|
| **没有 CI 服务**，只有本地一键脚本 | 依赖人记得跑 | `bash scripts/check_offline.sh` 已建（退出码可直接给 CI/pre-commit）；**未接入任何 CI 服务** |
| 保真度只在公开栈、每会话 3–5 点 | 覆盖不均 | 靠 `keyframe_on_checkpoint` 提高密度 |
| 没有历史版本对照 | NCC 低时分不清"回放坏"还是"版本变" | 需后端版本指针（B-03/B-04） |
| demo 是脚本驱动，不是真人 | 覆盖不到真人的犹豫、回看、误操作 | 需要一次真人会话（1 小时） |
| 工作台/浏览器检查是脚本点按 | 不覆盖真人审美判断 | 同上 |
