# 手动会话采集（真人操作 → 包 → 回放）

**一句话**：你自己在真 neuroglancer 页面上操作，采集器旁路记录；结束时一键落成
目录包；之后在全新页面里**只喂输入事件**把同一段操作放一遍，逐检查点比对。

- 采什么：`input.pointer` / `input.wheel` / `input.key` / `viewport.gesture` /
  `viewer.state-change` / `viewer.checkpoint` / `keyframe.capture` /
  `selection.change` / `evidence.bookmark`
- 不采什么：渲染过程（tile/chunk/mip）——已拍板不做，见
  [已定决策 §7](../已定决策.md)

## 用法（一条命令，不用填参数）

```bash
# 采集（数据/坐标/缩放/端口全部写死在 demo_manual.sh 里）
bash scripts/demo_manual.sh
# 终端会打印操作提示：安装脚本、打开数据页、保存后回放

# 回放最新一包
bash scripts/demo_manual.sh --replay
```

终端打印的内容长这样（远程访问会自动把 ssh 命令填好）：

```
1) 首次安装（点一次，弹“安装”确认；以后不再需要）
   http://127.0.0.1:8899/install
2) 打开数据页，正常校对（左下角会出现「CAVE 采集」）
   http://127.0.0.1:<ngport>/v/<token>/
3) 点面板上的「结束并保存」，然后在本机终端跑：
   bash scripts/demo_manual.sh --replay

远程访问（在你的电脑上先跑这一行，保持开着）：
ssh -N -L <ngport>:127.0.0.1:<ngport> -L 8899:127.0.0.1:8899 <user>@<host>
```

要点：

- 保存端口默认 **8899**；被占用时服务会自动改用 89xx，并以终端打印的 `/install` 地址为准。
- NG 端口由 tornado 随机分配，**不可固定**；终端打印的 ssh 命令已包含它。

## 两条硬约束（实测踩过）

1. **回放必须用录制时的视口**：拖动是按像素投递的，1280×820 录、1400×900 放，
   同一次拖动差 **200.61 nm**（远超 60nm 容差）；改成读包里的
   `session.start.viewport.css_px` 后 Δ=0.0。
2. **关键帧必须有 document-start 补丁**：不装脚本、只在控制台粘 recorder 时，
   `readback_via='gl_draw'` 虽能出图，但 `colored=0`（等于废图）。

## 两条注入路线（按“谁的手指在画布上”取舍）

| 路线 | 需要什么 | 关键帧像素 | 适合谁 |
|---|---|---|---|
| **CDP（`--cdp`）** | 自己启动 Chrome 带 `--remote-debugging-port`，并 `ssh -R` 把端口送上来 | ✅（`Page.addScriptToEvaluateOnNewDocument`，等价 document-start） | **自己机器 + 服务器**的场景，不想装扩展 |
| **本地自动打开（`--open`）** | 什么都不装；项目在本机、有图形界面 | ✅（`add_init_script`，等价 document-start） | **项目搬回本地后的首选**：一条命令，浏览器自己弹出来且已注入 |
| 控制台粘贴 | 什么都不装 | ❌（补丁太晚，`readback_via='gl_draw'` 但 `colored=0`） | 只想快速验证动作能录能放 |

本地用法（推荐，不需要任何隧道/扩展）：

```bash
bash scripts/demo_manual.sh --open     # 起 NG + 自动开一个已注入的浏览器窗口
#   退出方式：关掉那个窗口（服务随之退出）；无图形界面时自检 20s 后自动退出
bash scripts/demo_manual.sh --replay   # 保存后回放最新一包
```
实测（无显示器的服务器上）：`[open] 浏览器已打开（无头），注入 patched=True`；
本地有 DISPLAY 时会开真窗口。用的是 Playwright 自带 Chromium（不是你的 Chrome）。

CDP 用法（服务端 `bash scripts/demo_manual.sh --cdp`，终端会打印完整命令）：

```bash
# ) 你电脑上：独立 profile + 调试端口（新版 Chrome 要求独立 profile）
google-chrome --remote-debugging-port=9222 --user-data-dir=/tmp/cave-profile
# ) 建隧道：-R 把 9222 送上服务器，-L 把数据页/保存端口带下来
ssh -R 9222:127.0.0.1:9222 -L <ngport>:127.0.0.1:<ngport> -L 8899:127.0.0.1:8899 <user>@<host>
# ) 在这个 Chrome 里打开数据页；服务端会自动注入并 refresh 一次
```

实测（2026-10-27）：注入前 `__caveGLPatched=false`；注入并刷新后
`patched=true / manual=true / recorder=true`，面板显示「录制中｜事件 4」。

**回放端的三种"不算分"标注**（都是如实标出，不判过也不判错）：

| 标记 | 判据 | 含义 |
|---|---|---|
| `pixel_unstable` | 彩色占比差 > 0.2 | 回放端分割层没加载完/不是同一个画布 |
| `color_mismatch` | rgb NCC < 0.95 但**亮度 NCC ≥ 0.95** 且彩色占比相当 | 结构一致、**分段配色不同**（实测 manual_2：亮度 0.963 / 色度 0.492） |
| 关键帧缺失 | 包里只有 `painted_partial` | 采集端那帧没画完 |

## 组件

| 文件 | 作用 |
|---|---|
| `scripts/demo_manual.sh` | 一键入口（固定数据/参数；`--replay` 回放最新包） |
| `scripts/cave_manual_server.py` | 起真 neuroglancer（**直连**）+ `/save`、`/install` 端点 |
| `scripts/build_manual_userscript.py` | 把 GPU 补丁 + recorder + 面板打成一个自包含脚本（供 `/install` 与 sink 模式） |
| `scripts/manual_boot.js` | 左下角面板：事件数/检查点/缺口 + 打检查点 + 结束并保存 |
| `scripts/replay_manual_session.py` | 读会话包，按检查点切段重放输入并比对 |

## 为什么是"直连"，不是"代理注入"

先做过代理版（代理 NG 页面、往 HTML 里插 script），**实测不可用**：

- 页面能加载、`window.viewer` 也在，但**从不发起 `/state` 请求**
  （Playwright 记录里 0 条），于是 Python 侧改图层/位置永远到不了浏览器
  —— `layers=[]`、`position=null`，关键帧全黑（`blank_readback`，mean=0）。
- 直连同一台 NG 一切正常。

另外，真 CAVE 的页面不会经过我们的代理，只能在页面内部注入。
所以代理版只保留为历史记录，不再维护。

## 三条实测到的坑（都写进了代码注释）

1. **GPU 补丁必须在 document-start 注入**。晚了
   `toDataURL()` 全透明（37 KB 的“图”，像素 alpha 全 0）。
2. **recorder 必须等 `window.viewer`**：所以在生成脚本里用 `waitViewer` 轮询，
   而不是把 recorder 直接跑在 document-start。
3. **面板点击不能进输入流**：面板带 `data-cave-ui="1"`，recorder 跳过落在它
   里面的 pointer/wheel/key 事件；否则「打检查点」会被记成画布点击，回放时
   真的去点画布。

## 回放的判据（有哪些账要分开记）

| 检查 | 判据 | 不可比时怎么办 |
|---|---|---|
| 起点 position 还原 | Δ ≤ 60 nm（≈15 体素@4nm） | — |
| 每段 position | Δ ≤ 60 nm | — |
| 每段非位置字段 | 朝向/布局/图层/坐标系一致（`rsq.compare`） | 列出 `failed` |
| 段末像素 | **闭环**比到 `rgb NCC ≥ 0.95` | 若彩色占比差 > 0.2（回放端只剩 EM 或换了 canvas）→ 记 `pixel_unstable`，**不计分**，但必须打印出来 |

像素为什么必须闭环：实测有一次位置/尺度完全对上（Δ0.03 nm），但回放端还停在
**粗 mip 块状图**上——一次读取的 rgb NCC 只有 0.87；等瓦片到位后 1 次就读到
0.9964。灰度 NCC 在那种情况下仍有 0.98，所以只看灰度会把“细节没到”报成
“几乎一样”。

## 实测读数（2026-10-26，公开 minnie65）

一次 22 秒的“脚本扮演真人”会话：97 事件（pointer 23 / wheel 3 / key 5 /
gesture 3 / state-change 15 / checkpoint 6）、4 张关键帧（2 `captured`，
2 `painted_partial`）、0 缺口。

回放（重复运行结果一致）：

```
RESULT: PASS
起点 Δ0.00 nm
段 session_start→manual_2  Δ0.00 nm ｜ rgb NCC 0.9964
段 manual_2→manual_3       Δ0.03 nm ｜ rgb NCC 0.9739
段 manual_3→session_end    Δ0.03 nm
段 session_end→session_stop Δ0.03 nm
```

长会话用 `--start/--end` 按检查点分段；默认纯输入整段回放可能受 wheel 动画漂移影响，
`--reanchor-gesture` 提供可选的相机校正。

## 已知不能

- **工具切换**：本构建 `viewer.tool` 不存在，工具态读不到；split/merge 语义
  要可写后端（C0）。
- **提交链路**：`edit.request/ack` 需要可写后端，公开数据没有。
- **回放需要数据可达**：包记的是数据源 URL；回放机连不到（比如 CAVE 私有
  `graphene://`）时，position/尺度仍可比，但图是空的。
- **像素不可比的帧要标**：`pixel_unstable` 不是“通过”，只是“这一帧不能用来
  下结论”。
