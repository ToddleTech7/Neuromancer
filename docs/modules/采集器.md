# 模块：采集器（`cave_recorder.user.js`）

更新：2026-10-26 · 当前版本 **v0.9** · 能力状态以 [当前进度](../当前进度.md) 为准，本页只讲**这个模块内部**的不变量。

## 职责

在 Neuroglancer 页面里**旁路**记录"人看到什么、点了什么、提交了什么"，产出可回放的事件流。
**不做**：不做判断、不做语义分段、不改视野/选择/分割；采集故障必须 fail-open（不阻断校对）。

## 接口

**注入**：两个脚本，顺序不能反。

| 脚本 | 时机 | 作用 |
|---|---|---|
| `cave_gpu_patch.js` | document-start | 把 `preserveDrawingBuffer` 强制为 `true`（否则 readback 全透明） |
| `cave_recorder.user.js` | document-start | 记录器本体，暴露 `window.__caveRecorder` |

**公共 API**（页面里调用）

| 方法 | 作用 |
|---|---|
| `start()` / `stop()` | 开始/结束一段会话 |
| `emit(type, payload)` | 注入自定义事件（工作台也走这里，不碰 NG 内部） |
| `keyframe(moment)` | 立刻抓一张画布 |
| `checkpointNow(reason)` | 立刻存一个完整 state 快照（回放对照点） |
| `setConfig(patch)` | 运行中改粒度，发 `collector.status{config_change}` 留痕 |
| `status()` / `capabilities()` | 当前配置 / 哪些能力是 `available`/`partial`/`needs_fork` |

**配置（生效值随包走，下游不用猜默认）**

| 键 | 默认 | 含义 |
|---|---|---|
| `move_sample_ms` | 50 | move 采样间隔；`0`=全量。端点（down/up/click）始终全量 |
| `wheel_burst_gap_ms` | 400 | 滚轮聚合成一次 burst 的间隔 |
| `keyframe_on_checkpoint` | false | 每个 checkpoint 抓一张图（保真度需要）；≈120 MB/小时 |
| `full_state_on_change` | true | 每个状态变化存**完整 state**；≈1 MB/小时 |

URL 覆盖：`?cave_move_ms=0&cave_kf=1&cave_full_state=0`；运行时用 `setConfig()`。
上限：`MAX_EVENTS=200000`、`MAX_CHECKPOINTS=400`。超了记 `dropped`/`checkpoint_dropped`，
同时把 `overflow`（总数 + 首次丢弃时刻 + 上限）带进 `session.end`；`seq` 在丢弃时也递增，
所以下游 `seq_gaps` 能看到断档（旧实现 seq 仍连续，会给出“没中断”的假象）。
缺口 `gaps[]` 在回到正常时补 `t_end`，包里自带时长。`inspect_pack` 会把这些打成告警。

## 设计要点（改代码前必须守住）

1. **recorder 内存中事件只追加**，每条带 `seq`（单调，缺口显式记）与 `t_wall`（浏览器墙钟）；落成目录包时是一次快照重写。
2. **一个状态变化 = 一条 `viewer.state-change`，并且带完整 state**。这是"复刻"的单位：
   - `state_sha`（FNV-1a）用于去重；
   - `state_bytes` 记成本；
   - 缺 `position/layers/dimensions/layout` 时打 `state_partial`，**不许**当成可恢复；
   - 超过 256 KB 先降级：丢 `source.state`/`segmentColors`/过长 `segments`，标 `state_truncated`；降级后仍超才标 `state_omitted:'too_large'`。
3. **摘要不是 state**。摘要（位置/尺度/朝向/图层名）只够"跳到附近"，恢复不了布局与图层内部状态。
4. **关键帧要在有 draw 的那一帧之后读**，且必须已打 GPU 补丁；否则如实记 `blank_readback`。
5. **图与 state 的绑定要“钉”，不靠时间猜**（L1，2026-10-26）：
   - 快门那一刻同步取 `fullState()` → `state_sha`；`state_in_stream` 说明它是否已在事件流里；
   - **不在流里就随 shot 存一份完整 `state`**，否则那一刻永久丢了（回放只能按 3s 就近猜）；
   - `state_age_ms` 记录快门与上一次入流 state 的间隔（越大说明该帧越可能没入流）。
6. **拍前要等“画面对应这个状态”，且不许假装**（三个参数随包走）：
   - `keyframe_paint = {colored_min, stable_eps, timeout_ms}` 写进 `session.start.config` 与 `manifest.config`；
   - 判据是 **彩色占比达标 + 相对上一张变过了**（拿上一张的 16×16 拇指图当参数）——
     只看彩色会把“上一帧的旧画面”当已画完（旧画面本来就有颜色）；
   - 等不到就落盘 `capture_status='painted_partial'` + `paint_timed_out`，图上还在但不许当证据；
   - `moment === 'pre_submit'` 或**未打 GPU 补丁**时不等（前者语义是“编辑执行前”，
     等下去会拍到提交之后；后者 readback 本来就拿不到像素）；
7. **不采周期心跳**。空闲由离线 `idle_segments` 从输入时间戳算——心跳区分不了"人走了"和"采集器死了"。
8. **事件名以 RF01–RF15 为准**（点号命名），旧名写 `legacy_type`，下游统一用 `cave_session_pack.ctype()`。

## 实现入口

| 关注点 | 位置 |
|---|---|
| 采样主循环 | `sampleAll()`（每 500ms 一次状态/选择/鼠标比对） |
| 完整 state | `fullState()` + `state_sha`/`state_partial` |
| 手势聚合 | `gestureBuffer` → `viewport.gesture`（drag/click/zoom + start/end view ref） |
| 关键帧 | `captureShot()` + `waitPainted()`/`contentStats()` + `drawUrlLooksBlank()` |
| 快照 | `checkpoint(reason)` → `viewer.checkpoint` |
| 配置 | `CONFIG_DEFAULT` / `readConfigFromUrl()` / `setConfig()` |
| 图层字段 | `layerInfo()` → `layerStyle()` / `sourceInfo()`（v1.1） |

### 图层与视图字段（v1.1 补的，改之前先看这里）

两层结构，**都不要塞进 `vp` 顶层**：

```text
layers[] = { name, type, visible, opacity, source, segments_count,
             source_detail?,   // 有值才出现
             style? }          // 有值才出现
viewpoint += { showSlices, partialViewport, crossSectionDepth }
```

三条硬规矩：

1. **不复制大东西**。`source_detail` 只存 `{url, has_state}`，**不复制 `source.state` 本体**；
   `segmentColors` 只存 `segmentColors_count`。state 本体已经在 `state_sample.state` 里。
2. **空字段不写**。没有 `style` 的图层就不该多出 `style: {}`——否则每条 state-change
   都多几十字节，十几万条就是几 MB。
3. **旧字段一个都不能动**。`source`/`visible`/`opacity` 的下游消费方（join/派生）
   还在用旧形态；新字段是**纯增益**，只能加、不能改语义。

为什么必须有 `source_detail`：旧版对**对象型 `source`**（graphene 的 `{url, state}`）
直接返回 `null`，图层摘要里只剩下名字——看不出是哪个 graph。这是实现缺陷。

验证：`python3 scripts/verify_layer_fields.py`（17 项，about:blank 里跑构造对象，不联网）；
真实取值形式随构建而定，未在真实 graphene 上核过——见
[PRIVATE_NG_ADAPTER](../私有扩展接入.md) 第 5 节。

### 界面状态与外部扩展口（v1.2）

**`ui.state`**——canvas 以外的东西（用户 2026-10-29 拍板：像素只算 canvas，但工具/侧栏/通知要记）：

| 字段 | 来源 | 为什么 |
|---|---|---|
| `ui.panels[]` | `.neuroglancer-rendered-data-panel` 的 `getBoundingClientRect()` | `viewport{}` 只记最大的那个 canvas；split view 时每个 pane 尺寸不同 |
| `ui.tool` | `.neuroglancer-tool-palette-dropdown` / `.neuroglancer-annotation-tool-status` | 开面板/切工具时 `position` 可能一点不变 |
| `ui.notices[]` | `[data-cave-notify]` → `.neuroglancer-status-overlay` | 通知属于“人看到了什么”，不是 state |

**两条硬规矩**：

1. **单独节拍 1s**（`ui_interval_ms`），不跟 200ms 跑：`getBoundingClientRect()` 会强制同步
   layout，在 NG 这种重渲染页面上 5/s 是白花钱。
2. **拿不到就不记**。`ui.notices` 两个容器都没有就不写这个字段，不用 `textContent` 猜。

**`ext.snapshot`**——采不到的私有状态（Brush 候选/局部 Undo/合并计划/in-flight）的**唯一入口**：

```js
window.__caveRecorder.registerProvider('brush', () => ({rev: 3, candidates: [...]}));
```

- 注册了才采，**没注册零开销**；
- 值不变不重发（200ms 调 30 次 → 3 条）；
- 抛错只报一次 `collector_status.provider_error`，30s 内不重试（不刷屏）；
- 对方暴露了 `window.__caveSnapshot` 就**自动挂上**。

**`api.capability`**——`/undo/capabilities`、`/edit_groups` 的**响应体**（≤4000 字）。
“组 Undo 到底有没有”只能看服务端响应，不能从前端调用存在推断。

验证：`python3 scripts/verify_ui_and_providers.py`（14 项，本地 demo NG + 假能力端点）。

## 验证（结果见 [文档地图](../目录.md#验证结果)）

| 断言 | 守住什么 |
|---|---|
| 每个 `state-change` 都带完整 state | 复刻前提不被悄悄退化 |
| 可直接恢复的 state ≥ 5（实测 12/12） | 完整 state 真含 `position/layers/dimensions/layout` |
| 残缺 state 必须带 `state_partial` | 不把"半份 state"当可用 |
| 50ms 下 200 连发只落 1 条 / 全量落 200 条 | 粒度开关真的生效（含 `Number(null)===0` 这个坑） |
| 关键帧 `capture_status=captured` 且 `readback_via=raf_preserved` | 图是真像素，不是空白 dataURL |
| 每张图都能精确恢复（`state_in_stream` 或自带完整 `state`） | 图↔state 的绑定是构造的，不是按时间猜的 |
| 落盘带 `content{colored,mean,std,thumb16_sha}` 与 `keyframe_paint` | “画完没”是可查的量，不是口头假设 |
| 要么 `paint_settled=true`，要么 `capture_status='painted_partial'` | 未画完的帧不会不带标记地流进数据 |
| `input.key` 带 `action`（如 `x+` / `z+` / `snap`） | 守“字段采了但永远是空”：`inputEventBindings` 不是 Map，写成 `binds.get()` 拿不到 |
| 回放对比的 `content_mismatch` 必须为空 | 关键帧不是在“还没画完”的时候拍的 |
| `session.start.config` 与 `manifest.config` 一致 | 下游能判断这份数据的粒度 |

## 开放问题（做不到就写在 [待办事项](../待办事项.md)）

- **RF04 action id**、**RF07 工具态/草稿**、**RF10 V_loaded**：读不到内核，只能近似或不做。
- `panel_id` 只有 canvas 序号，没有 panel 身份（2D/3D 混排时分不清）。
- 3D 视锥/裁剪未采（RF09 只到 2D 视口 + nm/px）。
- 超大 state（图层极多）会被 `state_omitted` 跳过——那时该点不可精确恢复。
  **实测 256 KB 上限对公开 minnie65 富余（state 只有 726 B），但 graphene 带
  `source.state` 会大很多，未测**（见 [PRIVATE_NG_ADAPTER](../私有扩展接入.md) P0-4）。
- **“画完”仍是内容近似**：`colored_min` 判的是“分割叠加在不在”，判不了“瓦片是不是
  全到位”。真解是 `V_loaded`（要 fork）；在此之前用 `painted_partial` + 回放侧
  `motion_lag` 把已知的不可比情况标出来，不猜。
- **运动中拍的帧**天然与快门时 state 差一帧（`paint_stable=false`）：
  比对时不算错，回放侧单列为 `motion_lag`。
- **滚轮语义依赖绑定**（2026-10-26 实测，本构建）：裸 `wheel` **不改变**
  `crossSectionScale`（只动几 nm 的位置），缩放绑在 `ctrl+wheel`（6 → 0.54）。
  因此：① `input.wheel` 必须记 `modifiers`（已记）；② 把 wheel 直接当 `gesture.zoom`
  是错的，得看修饰键与尺度是否真变了；③ 动作回放必须重放修饰键。
- **工具态不可读**：本构建 `viewer` 上没有 `tool` 字段，所以“当前工具/工具切换”无法
  从插件侧验证（RF07 仍需改源码）；而 split/merge 语义要可写后端才能验（待 C0）。
  目前能验的键盘语义：`arrowleft/right = x±`、`arrowup/down = y±`、`comma/period = z±`、
  `bracketleft/right = t±`、`keyz = snap`（均以 `action` 落到 `input.key`）。

## 状态记录方式（v1 起双通道）

- **订阅**：`viewer.state.changed`（本地 NG 2.41 是 `{handlers: Set}` 形态，标准 Signal 则
  用 `addListener`）。变化后去抖 `semantic_debounce_ms`（默认 100ms）再采样，
  事件标 `trigger: subscribe`。作用是把“离散变化”（选中集/图层/布局）从 600ms 采样窗口里救出来。
- **轮询兜底**：`state_interval_ms`（默认 600ms，可设 0 关闭）。订阅丢了
  （viewer 重建/旧版 NG）也不会整段空白；事件标 `trigger: poll`。
- 两条通道共用同一个 `R.last.state` 去重 sig，否则会互相吞掉对方的变化。
- 实测：一次层加载+定位+选中，`state.changed` 回调约 269 次，去抖后落 4 条 state-change。

## 关键帧触发（v1 起：语义触发，不是按帧）

| `moment` | 什么时候拍 |
|---|---|
| `manual` | 面板「截图」/ `R.keyframe()` |
| `checkpoint` | 每 30s 的检查点（`keyframe_on_checkpoint` 开时） |
| `pre_submit` / `post_submit` / `submit_failed` | 提交前后（`hookFetch` 里） |
| `scale_change` | `crossSectionScale` 或 `projectionScale` 跨 ≥2 倍 |
| `layer_change` | 图层可见性集合变化 |
| `selection_change` | 选中集变化 |
| `dwell` | 视图中心（100nm 取整）+ 选中集 + 可见层都不变 ≥ `dwell_ms`（默认 5s） |

同类语义触发 1.5s 内限流；`viewer.dwell` 事件带 `duration_ms`，可直接算停留时长。
关闭方式：`semantic_keyframe=false` 或 `dwell_ms=0`（面板设置里也有）。

## 为什么没有 1 Hz 心跳

2026-10-26 已废除（见文件头注释）：心跳也是采集器发的，**分不清“人走了”与
“采集器死了”**；而且实测占事件流 28%。替代：

- 人是否在操作：输入事件时间戳算 `idle_segments`（离线可重算）；
- 采集器是否在跑：`seq` 连续性 + 宿主侧轮询 `R.status()`；
- 切页/断网：`collector.status` + `gaps[]`（带 `t_end`）。

## 草稿落盘（防崩溃丢整段）

- 每 `draft_ms`（默认 30s，可设 0 关闭）把 `seq > R.draftSeq` 的事件增量 POST 到
  `window.__caveDraftUrl`（构建时由 `__caveSaveUrl` 推出 `/draft`）。
- 失败时把 `draftSeq` 回退，下一次重发；`stop()` 前再冲一次。
- 服务端按 session 覆盖写 `_draft_<session>/events.jsonl`（按 seq 去重），
  正式保存成功后删除草稿。
- 图也增量传（一次最多 8 张，服务端按 `shot_id` 去重），崩溃最多丢最后 30 秒的图。
- 恢复：`nx.py recover`（事件/state/缺口/图都在）。
