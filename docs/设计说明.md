# 项目设计

> 只讲"为什么这样设计、边界在哪"。怎么用见 [使用说明](使用说明.md)。

## 一、要解决的问题

CAVE 的校对操作**结果**在服务端日志里（谁把哪两段合了/拆了），但**过程**不在：
人先看哪里、看了多久、为什么合、为什么放弃、改判了几次。

本项目只采**过程**，并且要满足两个硬要求：

1. **不改变校对员的工作方式**（旁路，只读，不改请求、不改渲染）；
2. **可回放**——同一段操作能在全新页面里重放，并对上"当时那个画面"。

## 三、五条不变量（改代码时必须守住）

### 1. 图 ↔ state 的绑定是**构造**出来的，不靠时间猜

快门那一刻同步取 `fullState()`：如果这个 state 已经在事件流里（`state_sha` 相同），
只存 `state_id`；不在流里，就**随图存完整 state**。所以任何一张关键帧都能精确恢复，
`state_age_ms` 只是参考量。"等多久"降级为可选尝试，结果记进 `paint_settled`。

### 2. 每个状态变化都带**完整** state

不是摘要。约 0.5 KB/次，一小时 1–2 MB。代价很小，换来"任意时刻可恢复"。

### 3. 不可比的帧必须**单列**，不许静默混进统计

| 标记 | 含义 | 后果 |
|---|---|---|
| `painted_partial` | 拍的时候彩色占比未达规则 | 保留图、不进保真度均值 |
| `motion_lag` | 拖动中拍的，与快门 state 差一帧 | 不算回放错 |
| `pixel_unstable` | 回放端彩色占比与录制差 >0.2 | 不计分，但必须打印 |

### 4. 动作有效性地板：动作没改变 state 就不算通过

"位置误差 0" 可能是"两边都没动"。所以回放前先验：拖动 Δ>1nm、滚轮尺度变化 ≥0.1%、
键盘产生绑定动作（`x+` / `z+` / `snap`）。**修饰键是动作的一部分**（本构建里
裸 `wheel` 不缩放，缩放绑在 `ctrl+wheel`）。

### 5. 回放必须用**录制时的视口**

拖动按像素投递。1280×820 录、1400×900 放，同一次拖动差 **200.61 nm**（容差 60）。
所以回放读包里的 `session.start.viewport.css_px` 建同尺寸上下文。

## 四、注入：三条路，一条主路

| 路线 | 机制 | 时机 | 像素 | 用途 |
|---|---|---|---|---|
| `--open`（**主路**） | 我们启动浏览器 + `add_init_script` | document-start | ✅ | 本地首选 |
| `--cdp` | 连你自己 Chrome 的调试端口 + `Page.addScriptToEvaluateOnNewDocument` | document-start | ✅ | 不装扩展、仍用你自己的浏览器 |
| 控制台粘贴 | 手动 eval | document-idle | ❌ | 只验动作 |

**已证伪的一条**：反向代理 NG 页面并往 HTML 里插 script。页面能开、`window.viewer` 在，
但**从不发起 `/state` 请求**（Playwright 记录 0 条），Python 侧改图层永远到不了浏览器
（`layers=[]` / `position=null`，关键帧全黑）。且真 CAVE 的页面不可能经过我们的代理。

> 结论：注入不可省（没有它就没有采集），但**本地可以完全自动化**（`--open`）。

## 五、模块边界（每个文件"该做什么 / 不该做什么"）

| 模块 | 该做 | 不该做 |
|---|---|---|
| `cave_recorder.user.js` | 旁路记事件/状态/关键帧；暴露 `__caveRecorder` | 读 viewer 内部结构、改渲染、拦请求 |
| `cave_gpu_patch.js` | 只改 `getContext` 的 `preserveDrawingBuffer` | 碰其它 GPU 状态 |
| `manual_boot.js` | 面板 + 配置 + 上报保存 | 采集逻辑（全在 recorder） |
| `cave_session_pack.py` | 目录契约 + **白名单**落盘 | 加工语义（派生在 episodes/derive） |
| `cave_episodes.py` | 归一化 / 切分 / no-op 分级 | 判断"该不该合并" |
| `cave_join.py` | 会话↔op log 三级匹配 + 时钟估计 | 改事件内容 |
| `replay_state.py` | 指纹、字段比对、恢复点选择 | 开浏览器、做断言 |
| `verify_*` | 只做断言与报告 | 生产数据 |
| `cave_replay_viewer.py` | 只读回放 + 写门禁 | 写远端 |

外部 UI 模块另有一条约束：**只经 `__caveRecorder.emit` 写**，
不读 viewer 内部、不改渲染；候选来源必须过白名单与禁词扫描（label/outcome 不得进产物）。

## 六、一次采集的数据流

```
操作 ──► recorder.onPointer/onWheel/onKey
            │  去重/采样（move_sample_ms=0 全量）
            ▼
       emit(input.*)  ──► viewer.state-change（完整 state + sha）
            │                    │
            │                    └─► checkpoint（打点时：全量 state）
            ▼
       checkpointNow ──► captureShot：等画到内容阈值 → 读像素 → 钉 state → 存图+content
            │
            ▼
       面板「结束并保存」──► exportWithImagesJSON ──► POST /save ──► 目录包
            │
            ▼
   replay_manual_session：恢复起点 state（唯一一次）→ 只喂输入 → 逐检查点比对
```

## 七、与"改源码 / 改后端"的边界

| 想要 | 现状 | 需要什么 |
|---|---|---|
| 判断"画了哪些 chunk" | 做不到 | 改 NG 源码（chunk 回调） |
| 采集当前工具（merge/split） | 做不到 | `viewer.tool` 不存在 → 改源码 |
| 提交链路 / attempts | 没有 | 可写后端（C0） |
| 完整复刻 CAVE 画面 | 公开数据可以 | 回放机需能访问同一数据源 |
