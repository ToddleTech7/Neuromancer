- **“回放画面和当时不一样”的排查（同日，用户指出）**：用户说当时看到的是“电镜背景 +

    左下 3D **无 mesh**，t=35 s 才画出（蓝/粉/绿三个段）。快门那一刻本来就没有
    mesh，所以 `rec_*.png` 和回放视频里都没有——不是回放丢了。
  - 结论：需要改动的是**采集时机**（打点前等铺满 / 等 mesh），不是回放器。

- **修正上一条结论：真的是回放器的缺口（同日，用户追问后重查）**。`shot_6.png` 里
  2D 是“EM 灰底 + 选中段彩色”、3D 有 mesh，与用户描述完全一致——采集端没问题。
  - 根因：**选中集（segments）没被重放**。回放只喂 pointer/wheel/key，起点用
    `session_start` 的 state（`segments=[]`）；NG 在“选中为空”时显示全部分割（全彩）
    且不画 mesh。`selection.change` 记的是**悬停的段**（随鼠标变），不是选中集——
    第一版拿它当选中集，错了（跑到一半发现 ids 一直只有一个且来回跳）。
  - 修：`segments_of_state()` 从视角快照取 `layers[].segments`，**每段末**对齐一次
    （`sel` 指令，只改 segments 不重建层）；段末同时对齐 `projectionScale` /
    `projectionOrientation`（否则 3D 面板漂移，占 1/4 像素）。
  - **卡死也一并修了**：有选中段时 NG 会拉 3D mesh（~35 s），页面忙时 `page.evaluate`
    **无超时、无限挂**（实测卡 9 分钟、CPU 0%）；一条 `mouse.move` 也能卡满默认 30 s。
    → 加 `eval_timeout()`（SIGALRM 打断）、动作 `default_timeout(500ms)`、
    `play_events(tolerant=True)`、起点先清空 segments。
  - 实测（`--start manual_2 --end manual_3 --mesh-wait 30`）：位置 Δ=0.0 nm、输入 198 条
    7.6 s（之前会卡死）、`live_manual_3.png` 与 `rec_manual_3.png` **肉眼看基本一致**
    （EM+粉圈+蓝内区；3D 蓝色管状 mesh + 粉色段）。像素仍 **rgb 0.837 < 0.95**，
    剩余差异在 3D mesh 的光照/细节（`layers` 仍报不一致）。
  - 未改默认：`colored_min`、`accept-ncc` 不动。待定：是否把 3D 面板单独拉出来比
    （含 mesh 的画面用统一 0.95 太严）。
  - 全量连跑实测（8 段）：前 4 段位置全 PASS（Δ=0.0 nm），像素 `state_change→manual_2`
    **rgb 0.919**（colored_rec 0.194 vs live 0.192，2D 完全对），`manual_2→manual_3`
    0.803；到第 6 段（474 条）被 mesh 加载拖到数分钟一条。加 `CAVE_MESH_SCALE=0`
    （demo server 关 mesh 渲染）开关备用，并在 USAGE 里改成**推荐分段回放**
    （`--start/--end` 一段一次，稳定且好定位）。单段实测 7.6 s / 198 条。
  - 仍未完成：全量连跑 + 视频的端到端一次跑通；`layers` 那项不一致原因（段末
    `sel` 与读状态的时序）待查。
  - 比对口径改分块：`CMP_JS` 支持 `regions`（比例框），默认只比 4panel 的 **2D 三块**
    （左下 3D 单列），`--compare-all` 回整图。同一段实测：整图 rgb 0.695 → 2D 三块
    0.916（colored_rec 0.071 vs live 0.074，着色一致）。
  - **结果不稳**：同一段重跑会在 0.71–0.92 之间跳，灰度 ncc 最低 0.649——回放端 EM
    瓦片/分割数据的加载完成度每次不同（NG 没有“加载完成”信号）。下一步应把像素比对
    改成“先等画面指纹连续两次一致再比”（现在只等 `colored ≥ 0.05`）。

## -10-27（本机可用性）：解释器选择 + macOS 有头修复（回归 7/7 PASS）

- **触发**：接手核查“公开数据上亲手操作并记录”能不能一条命令跑通，复现两个阻塞点。
- **阻塞点 1：解释器选错**。`demo_manual.sh` 只判“文件可执行”，本机 `.venv` 建好但
  包还没装时会被选中 → 直接报“缺少依赖”并退出；且 `PYTHON=python3`（裸名字）无效，
  因为 `[ -x python3 ]` 为假，仍会落回 `.venv`。
  - 修：改成“第一个能 `import neuroglancer, playwright` 的解释器”，裸名字用
    `command -v` 解析；全都不行时一次打印候选列表与安装命令；命中时打印 `[python] …`。
- **阻塞点 2：`--open` 在 macOS 永远无头**。有头判定只看 `DISPLAY` /
  `WAYLAND_DISPLAY`，macOS 两者通常都不存在 → 窗口里**无法操作**，只做 20s 注入自检。
  - 修：新增 `_has_desktop()`：`CAVE_HEADLESS`（1/0 显式覆盖）> macOS/Windows 默认有头
    > Linux 看 `DISPLAY`/`WAYLAND_DISPLAY`。
- **实际验证**：`_has_desktop()` 为 `True`；有头 chromium + `add_init_script` 打开公开
  minnie65 页，`__caveGLPatched` / `__caveRecorder` / 面板 `[data-cave-ui]` 三者均在；
  `CAVE_HEADLESS=1` 仍走无头自检；pytest **136 通过**；既有包复跑
  `sess_2026-10-26T15-33-02-256Z_j9uwd` **7/7 PASS**（起点 Δ0.0 nm，段末 rgb NCC
  0.9952 / 0.9975，各 1 次闭环），回放报告 `results/manual_replay/20261027_052001/`。
- **环境动作**：`pip install -r requirements.txt` 之后 `.venv` 的 playwright 版本升高，
  缓存里的 chromium 对不上（`chromium_headless_shell-1248` 缺失）→ 补跑
  `.venv/bin/python -m playwright install chromium`。已写入 USAGE A2 的排错行。
- **手动实测又撞到“窗口看不见 / 面板只显示一半”（同日下午）**：① `--open` 虽然
  有头，但 Playwright 不指定窗口位置 → 实测 bounds 左边 **-162**（部分屏外），
  且新窗口不抢焦点；② 写死 `viewport 1400×900` 比 13 寸 Mac 的可视区高
  （屏 1470×956，扣菜单栏 25 + Dock + 标签栏 ~90 后窗口最高 ~867），导致
  `fixed; bottom:12px` 的左下角面板被窗口下边裁掉一半——人看到的是“面板只有一半”。
  - 修：视口默认改 `1280×740`（`CAVE_WINDOW_SIZE` 可覆盖），窗口位置改由
    CDP `Browser.setWindowBounds` 设定（`--window-position` 会被 viewport resize 冲掉），
    加载后 `pg.bring_to_front()`。实测窗口回到 `40,40→1322,900`。
- **两个面板重叠（同日下午，用户第一眼就问）**：`cave_recorder.user.js` 自带右下
  「CAVE Recorder v0.9.0」面板（开始/停止/备注/截图/导出），`manual_boot.js` 又在左下
  加「CAVE 采集」（打检查点/结束并保存）——两套按钮同时存在，且旧面板的「停止」会
  截断会话、「开始」会清空已记事件。
  - 修 1：recorder 自己的面板补 `data-cave-ui`（之前**没有**这个属性，点它就等于在画布
    上点一下，会被录进去，回放时凭空多点）。
  - 修 2：`manual_boot` 把 `#cave-recorder-panel` 隐成 `display:none`，并把「备注」
    按钮补到左下，UI 收拢成一套。实测 DOM：`CAVE 采集 | 打检查点 | 备注 | 结束并保存`
    + `cave-recorder-panel → display:none`。
- **保存卡死 / 备注一闪就没（同日下午，用户实测撞到）**：
  - 根因一：**端口被抢**。本机 Qoder IDE 占着 `127.0.0.1:8899`，我们绑
    `0.0.0.0:8899` 居然也能成功（SO_REUSEADDR），但浏览器发给
    `http://127.0.0.1:8899/save` 被 IDE 那个更具体的监听接走 → 永远停在“正在保存…”。
    实测：`GET /ping` 超时；包里什么也没有。
    修：`_port_free()` 同时试 wildcard 和 `127.0.0.1`，`_pick_port()` 自动换到空端口
    （实测启动打印 `[port] 8899 已被占用…改用 8900`），sink / /install / SSH 提示
    全部跟随实际端口。
  - 根因二：**备注用 `window.prompt`**，而 Playwright 默认 dismiss 所有 dialog，
    人看到的就是“点了又没了”、文本永远空。修：`addNote(textArg)` 支持外部传入文本；
    `manual_boot` 改用页内输入框（回车记下 / Esc 取消）。
  - 附带：保存加 `AbortController` 20s 超时 + 失败时提示“端口可能被占用”；
    “正在打包…”先渲染再同步导出，人不会以为卡死。
    验证：`GET /ping` → `{"ok":true}`，`POST /save {}` → 200 且真实落盘（已删测试包）。

## 2026-10-30 落包优化：临时目录 + 整体切换

同 session 重存原来先 `d.rename(.old_*)`，再在正式目录逐文件写；中途失败会留下半包。

现在 `pack_session` 先在 `out_dir/.tmp_*` 完整写事件、图片、索引、manifest 和 `打开.html`，
再备份旧包并 `rename` 成正式目录；写失败只删临时目录，旧包原样保留。
提交阶段仍是两次 rename，进程在极短窗口被杀时旧包在 `.old_*`、新包在 `.tmp_*`，
不会出现正式目录里的半包。新增 `test_failed_resave_keeps_old_pack` 与
`test_successful_resave_leaves_no_staging`。
