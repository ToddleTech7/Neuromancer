# 数据：存了什么、怎么存、怎么读

> 本页是**数据模型与读取方式**的唯一权威。能力边界见 [功能清单](功能清单.md)，
> 设计理由见 [设计说明](设计说明.md)，包契约细节见 [modules/pack_and_join.md](modules/会话包与关联.md)。

## 一次会话存成什么

**一个目录 = 一次会话**。目录名随便改（会话 ID 读 `manifest.json`，不从目录名推）。

```text
results/manual_sessions/<目录名>/             ← 实测 2165 事件 / 166 s / 4.6 MB
  打开.html               双击就能看：视角轨迹 + 全部事件时间线（自包含，无 JS 依赖）
  manifest.json          会话元数据：config / counts / health / provenance / integrity
  client/events.jsonl    事件流，一行一条 JSON（677 KB）；同会话重存时整份重写
  client/shots/shot_N.png  关键帧像素，1280×740（7 张，共 4.3 MB）
  client/shots/shots.jsonl 关键帧索引（7 条）：绑定哪个 state + 内容判据
  client/notes.jsonl     备注，一行一条（可为空）
  derived/               派生（可重算，删了不影响原始）
    episodes.jsonl       行为片段（每段一行）
    hover.json           指针停留区间 + 三态（ok / no_picked / no_samples）
    normalized.json      归一化事件流
    episode_policy.json  切分参数与版本
  replay/<时间戳>/        界面级回放产物（`nx.py replay` 生成，跟着会话走）
    report.json          逐段结果：Δpos / rgb NCC / attempts / 各类 skip 标记
    rec_<锚点>.png       录制时那一帧
    live_<锚点>.png      回放同一时刻那一帧
    final.png            回放结束整页截图
```

**原始 vs 派生**：`client/` 是采到的事实，`derived/` 是算出来的。派生删除后重跑即可，
每个派生产物都带 `policy_version`。

**体量估算**：本次 20.4 s 产生 403 KB（其中图占 86%）。按"每 20 秒打一个点"算，
1 小时约 20 MB；不打点只录事件的会话在 1–3 MB 量级。

## 事件流 `client/events.jsonl`

每条都带公共字段：`seq`（序号）、`t_mono`（单调毫秒，用于排序/去抖）、
`t_wall`（墙钟毫秒，用于对齐服务端日志）、`type`、`state_id`。

| type | 何时产生 | 关键字段 |
|---|---|---|
| `session.start` | 采集器启动 | `viewport{css_px,panel_px,dpr}`、`config`、`initial_state`、`collector_version`、`page` |
| `session.end` | 停止 | `counts`、`gaps`、`overflow`、`pending_writes` |
| `viewer.attach` | 绑上 viewer | `url`、`dimensions`、`viewer_version` |
| `viewer.state-change` | 视角变化（节流） | `state`（**完整**）、`state_sha` |
| `viewer.checkpoint` | 打检查点 | `state`、`state_sha`、`reason` |
| `viewer.focus` | 鼠标位置采样（变化才发） | `position`（画布坐标）、`page`（页面像素）、`picked`（指针下的段 ID）、`picked_miss`（在画布里但没压到段）、`picked_layer`；旧包的嵌套 `position` 由 `load_session` 展开 |
| `selection.change` | 选中集/`layerSelectedValues` 变化 | `selection{层名:{count,ids}}`（每层前 8 个 id） |
| `input.pointer` | down / move / up | `phase`、`button`、`buttons`、`pointer_id`、`pointer_type`、`x`/`y`（页面像素）、`panel` |
| `input.wheel` | 滚轮 | `dy`/`dx`、`delta_mode`、`modifiers`、`x`/`y`、`panel` |
| `input.key` | 按键 | `key`、`code`、`key_combo`、`modifiers`、`action`、`action_section`、`tool_context` |
| `viewport.gesture` | 手势聚合（拖/缩放段） | `kind`、`start_ms`/`end_ms`、`duration_ms`、`n_raw`、`path_px`、`net_px`、`view_changed`、`start_view`/`end_view` |
| `keyframe.capture` | 关键帧 | `shot_id`、`moment`、`image_ref`、`state_sha`、`state_in_stream`、`paint_*`、`content`、`capture_status`（图↔state 绑定在 `shots.jsonl`） |
| `evidence.bookmark` | 备注 | `text`、`note_id`、`state_id` |
| `draft.update` | 工具栏 multicut 草稿 | `layer`、`sources`、`sinks`、`raw` |
| `ui.state` | 界面状态变化（v1.2） | `ui.panels[]`（每个 pane 的 `[x,y,w,h]`）、`ui.tool`（`palette_open`/`items`/`status`）、`ui.notices[]` |
| `ext.snapshot` | 外部扩展口回调（v1.2） | `provider`（名称）、`value`、`value_bytes`、`truncated` |
| `api.capability` | 能力查询的**响应体**（v1.2） | `url`、`status`、`body`（最多 4000 字）、`truncated` |
| `private.journal` | 私有本机记录变化（v1.4） | `entries[]`：`key`、`bytes`、`sha`，小值带 `value`、大值只带 `value_head`（前 2000 字） |
| `api.request` / `api.ack` | **读**请求观察 | `kind`、`method`、`url`、`status`、`ms`、`server_date_ms`、`via` |
| `edit.request` / `edit.ack` | **写**请求（提交链路） | 同上，`write=true` 分流；带 `X-CAVE-Edit-*` 时额外有 `edit_group`/`edit_step`/`edit_request_id` |
| `edit.operation` | 从响应抽出的操作 id | `op_id`、`kind`、`request_id`、`via` |
| `api.error` | 请求失败 | `url`、`error` |
| `collector.heartbeat` / `collector.status` | 心跳 / 自检 | `events`、`gaps`、`visible` |

> `ui.state` / `ext.snapshot` / `api.capability` 是 v1.2 新增的不同来路，
> 分开看：
>
> | 事件 | 从哪里来 | 为什么单立一条 |
> |---|---|---|
> | `ui.state` | DOM（我们自己读） | 开面板/切工具时 `position` 可能一点不变，塞进 state-change 会被当成“没变化” |
> | `ext.snapshot` | 外部注册的只读函数（前端 hook） | 采不到的私有状态从这里进；**没注册就零开销** |
> | `api.capability` | `/undo/capabilities`、`edit_groups` 的**响应体** | “组 Undo 到底有没有”只能看服务端响应，不能从前端调用存在推断 |

> 读写请求必须分开（`edit.*` vs `api.*`）。混在一起，“提交链路”就无法单独对表。

### 视角快照 `viewpoint` 里的字段（`viewer.state-change` / `viewer.checkpoint`）

| 字段 | 含义 | 缺失时 |
|---|---|---|
| `position` / `position_nm` | 中心坐标（原单位 / nm） | `null` |
| `crossSectionScale` / `projectionScale` | 2D / 3D 缩放 | `null` |
| `crossSectionOrientation` / `projectionOrientation` | 朝向 | `null` |
| `crossSectionDepth` | 切片厚度（v1.1 新增） | `null`：NG 从未设过这个值 |
| `showSlices` | 是否显示切片（v1.1 新增） | `null`：同上（NG 2.41 里是可选属性） |
| `partialViewport` | 局部视口 `[x0,y0,x1,y1]`（v1.1 新增） | `null`：未开局部视口 |
| `nm_per_px` + `nm_per_px_method` | nm/px 及**推导依据** | `null` |
| `layout` / `dimensions` | 布局 / 维度单位 | — |
| `viewport{css_px,panel_px,dpr}` | 画布尺寸 | — |
| `layers[]` | 图层摘要（见下） | `[]` |
| `visibleLayers` / `selectedLayer` | 可见层名 / 选中层名 | `[]` / `null` |

`layers[]` 每项：`name`、`type`、`visible`、`opacity`、`source`、`segments_count`，
加上两个**有值才出现**的字段（v1.1）：

| 字段 | 内容 | 为什么有它 |
|---|---|---|
| `source_detail` | 对象 → `{url, has_state}`；多源 → 数组。**不复制 `state` 本体** | 旧版对对象型 `source` 返回 `null`，graphene 图层的数据源全丢 |
| `style` | `baseSegmentColoring`、`baseSegmentHighlighting`、`selectedAlpha`、`notSelectedAlpha`、`objectAlpha`、`colorSeed`、`segmentDefaultColor`、`segmentColors_count` | 颜色/透明度不同，回放像素就差；`segmentColors` 可能几百项，**只记条数** |

> `style` / `source_detail` 只在图层真有这些属性时出现，空图层不会凭空多出字段。
> 验证：`python scripts/verify_layer_fields.py`（17 项，不联网）。

## 关键帧 `client/shots/`

### 什么时候拍

> 完整规则、阈值依据、每张图的 `detail` 字段、怎么调参：见 **[关键帧规则](关键帧规则.md)**。
> 下面是速查。

| 触发 | 条件 | `moment` | 默认 |
|---|---|---|---|
| 检查点 | 点「打检查点」/ 会话开始结束时 | `checkpoint` | 开 |
| 缩放跨档 | 与**上次拍照时**比，`crossSectionScale` 或 `projectionScale` ≥ **1.5 倍** | `scale_change` | 开 |
| 视角移动 | 中心移动 > **半个屏幕**（`nm_per_px × 画布宽度 × 0.5`） | `view_change` | 开 |
| 视角转动 | 切片或 3D 相机朝向变化 > **10°** | `view_change` | 开 |
| 图层显隐 | `visibleLayers` 变了 | `layer_change` | 开 |
| 选中集变化 | 分割选中集变了 | `selection_change` | 开 |
| 停留 | 中心 + 选中集 + 可见层都不变 ≥ 5 秒 | `dwell` | 开 |

每条 `shots.jsonl` 还带 `detail`：为什么拍、变化多少（比值 / 移动 nm / 转向角 /
选中集增删）。字段字典见 关键帧规则 §三。

**2D 截面和 3D 相机一视同仁**：平移、转动、缩放任何一项变了都会拍。
同类触发 1.5 秒内限流，所以连续拖动只会每 1.5 秒留一张，不会每帧一张。

比较基准**只在上次真拍了之后才推进**——否则滚轮一格 1.1 倍，
相邻两帧永远不到 1.5 倍，连续放大 10 倍也一张不拍。

缩放值从哪来记在 `vp.scale_source`：`state`（正常）/ `viewer`（兜底）/
`none`（拿不到，此时该轴为 `null`）。`partial` 表示两个轴只有一个拿到。
拿不到的那个轴不参与判据，另一个轴照常工作。


`shots.jsonl` 一条的真实样子：

```json
{"shot_id":"shot_3","image_ref":"shots/shot_3.png",
 "state_id":10,"state":null,"state_in_stream":true,"state_sha":"f37bd844",
 "content":{"colored":0.723,"mean":93.27,"std":58.82,"thumb16_sha":"c96a63fe"},
 "capture_status":"captured","paint_settled":true,"paint_waited_ms":1200,
 "readback_via":"raf_preserved","w":1280,"h":820,"state_age_ms":380,
 "moment":"checkpoint"}
```

| 字段 | 含义 |
|---|---|
| `image_ref` | 图在包里的相对路径（PNG 文件） |
| `state_id` | 指向事件流里已有的完整 state |
| `state` | 若那一刻的 state 不在流里，就**随图存完整 state**（此时 `state_id` 可能为空） |
| `state_sha` | 短哈希，用于和人打的点对齐、去重 |
| `content` | `{colored, mean, std, thumb16_sha}` —— 判断"画到没有" |
| `state_truncated` | 超大 state 的降级原因（`layer.source.state`/`layer.segmentColors`/`layer.segments`），没降级为 null |
| `capture_status` | `captured` / `painted_partial` / `blank_readback` |
| `paint_settled` / `paint_waited_ms` / `state_age_ms` | 等瓦片的过程量，仅供参考；绑定依据是 `state_sha` |

抓图状态的含义：

- `captured`：彩色占比达到阈值，**只有它能用于像素比对**；
- `painted_partial`：拍到的时候还没画完（实测早期帧 colored 只有 0.017），留档但不计入；
- `blank_readback`：读回全黑（GPU 补丁没生效，见 [使用说明](使用说明.md) 排错）。

## 元数据 `manifest.json`

| 键 | 内容 |
|---|---|
| `config` | 采样粒度（`move_sample_ms`）、关键帧规则（`keyframe_paint`）、是否全量 state |
| `counts` | 各 `type` 的条数 |
| `health` | 缺口/心跳自检汇总（含 `dropped` / `gaps_total_ms` / `gaps_open`） |
| `provenance` | 来源字段：`client_process` 在真实 `/save` 时为 `real`，其余未声明为 `unknown` |
| `integrity` | 事件/备注/索引文本 SHA256、PNG 本体 SHA256 与数量；`nx.py verify-pack` 校验 |
| `created_at_utc` | 落盘时间 |

## 怎么存（写路径）

```
浏览器内 recorder（内存，不落盘）
   └─ 面板「结束并保存」
        └─ exportWithImagesJSON()       图转 dataURL
             └─ POST /save（127.0.0.1:8899）
                  └─ cave_session_pack.pack_session()
                       ├─ 隐藏临时目录（.tmp_*）
                       │    ├─ events.jsonl      逐条 append
                       │    ├─ shots/shot_N.png  dataURL 解码写盘
                       │    ├─ shots/shots.jsonl 索引里只写 image_ref
                       │    └─ manifest.json     白名单字段 + sha256
                       └─ 完整落盘后：旧包 → .old_*，临时目录 → 正式目录
```

写入约束：

1. **先写临时目录**：完整落盘并校验后再整体切换；写失败不留下半包；
2. **白名单落盘**：只写已知字段，`label` / `outcome` 这类标注进不来；
3. **图存文件、索引存引用**：JSON 里不嵌 base64，包体积可控；
4. **不可比的帧标状态而不是丢弃**：`painted_partial` / `blank_readback` 都留档 + 标状态。

## 怎么读

### 先看包（推荐第一步）

```bash
python3 scripts/inspect_pack.py                 # 最新一个包
python3 scripts/inspect_pack.py <包目录> --json  # 给脚本用
```

实测输出（本机那个 20.4 s 的包）：

```
会话：sess_2026-10-26T15-33-02-256Z_j9uwd ｜ 采集器 0.9.0 ｜ 402.6 KB ｜ 89 事件
时长：20.4s ｜ 完整 state 变化 14 次 ｜ 备注 0 条 ｜ integrity present

事件构成：
  input.pointer 20 · collector.status 16 · viewer.state-change 14 · viewer.focus 13
  viewer.checkpoint 6 · keyframe.capture 4 · viewport.gesture 4 · input.key 4
  input.wheel 3 · selection.change 3 · session.start 1 · session.end 1

锚点（能用于回放的）：5
  [ok] session_start state_id=2 / manual_2 10 / manual_3 14 / session_end 14 / session_stop 14
  被丢弃的 checkpoint（没有完整 state）：1（session_start state_id=0）

关键帧：4 张（可用于像素比对 2 张）
  shot_1 painted_partial 0.017 / shot_2 painted_partial 0.017
  shot_3 captured        0.723 / shot_4 captured        0.723
```

### 脚本读整包

```python
import sys; sys.path.insert(0, 'scripts')
import cave_session_pack as csp

pack = csp.load_session('results/manual_sessions/<id>')
pack['events']    # 89 条，按文件顺序
pack['shots']     # 4 条索引（image_ref 是相对包根路径）
pack['notes']     # 备注
pack['manifest']  # config / counts / health / integrity

# 只取"人打过的、且带完整 state 的"锚点：
[c['reason'] for c in pack['events']
 if c['type'] == 'viewer.checkpoint' and (c.get('state') or {}).get('position')]
# → ['session_start', 'manual_2', 'manual_3', 'session_end', 'session_stop']
```

这条过滤是必需的：实测包里**第一个自动 checkpoint 只有 `{"layout":"4panel"}`**
（那时 NG 还没吐出完整 state），不过滤就会拿到一个没有位置的假锚点。

### 回放（复用同一套读取）

```bash
python3 scripts/replay_manual_session.py --pack <包目录> --headed
```

两个读取入口：`anchors_of(pack)`（带 position 的 checkpoint）、
`usable_shots(pack, dir)`（只收 `captured`，并把 `image_ref` 读回成 dataURL）。

### 人眼看

```bash
cat <包>/replay/<ts>/report.json          # 逐段 PASS/FAIL/SKIP
open <包>/replay/<ts>/rec_manual_2.png    # 当时看到的
open <包>/replay/<ts>/live_manual_2.png   # 重放出来的
```

### 往下游派生

```bash
python3 scripts/cave_episodes.py ...    # 归一化 + 切 episode + no-op + 悬停段
python3 scripts/cave_join.py ...        # 会话 ↔ 服务端 op log（三级匹配）
python3 scripts/nx.py export-csv         # 导出 events/episodes/hover CSV
python3 scripts/demo_export_samples.py  # 导出带 contact sheet 的样本卡
```

`cave_episodes.py` 落三样：`derived/episodes.jsonl`（每段带自己的 `hover`）、
`derived/normalized.json`、`derived/hover.json`（整段汇总）。

**`hover` 的口径（产物里 `caveats` 字段也带一份）**：

| 字段 | 含义 |
|---|---|
| `status` | `ok` / `no_picked`（有样本无值）/ `no_samples`——**“没人悬停”与“取不到值”必须分开** |
| `status_why` | 非 `ok` 时的人话原因 |
| `n_samples` / `n_with_picked` / `n_picked_miss` | 总样本 / 有段 ID / “在画布里但没压到段” |
| `segments[]` | 按 `total_ms` 降序：`id`、`layers`、`n_spans`、`total_ms`、`max_span_ms`、首末时间 |
| `open_spans` | 最后一次悬停没有后续样本（只能算到会话结束） |
| `n_not_segment_id` | `picked` 不像段 ID（如灰度值）的样本数，**单独计数不静默丢** |

读取要点：`hover ≠ 注意`；`viewer.focus` 是**变化才发**，停住没新样本，
所以时长是“到下一次变化”；短于采样点的划过会丢 → 次数与时长都是**下界**。

## 已知限制

| 现象 | 原因 | 处理 |
|---|---|---|
| 第一个 checkpoint 没有 `position` | NG 还没吐出完整 state 就打了点 | 读取时按 `position` 过滤（`anchors_of` 已做） |
| 关键帧 `painted_partial` 不能比重 | 拍的时候分割层没画完（colored 0.017） | 只拿 `captured` 做像素比对 |
| JSON 里找不到 base64 | 图落成 PNG，索引存 `image_ref` | 按 `image_ref` 读文件 |
| 拖动中间那张图和锚点对不上 | 抖动产生 `motion_lag` | 不用它判回放对错 |
| 回放端 `rgb` 低但灰度很高 | 分段配色跨加载不同（`color_mismatch`） | 标 skip，不算失败 |
| `hover` 全是 `no_picked` | 那一段录制的环境里没有可 pick 的层（如本地 demo），或指针确实都在空白处 | 看 `status_why`：`no_picked` 与「没人悬停」是两回事 |

## 缺口与丢弃（v1 起显式记录）

`gaps[]`（在 `session.end` 与 `manifest.collector` 里）每项：

| 字段 | 含义 |
|---|---|
| `t_wall` | 进入缺口的墙钟（ms） |
| `reason` | `page_hidden`（切走/后台标签）或 `network_offline`（断网） |
| `t_end` | **回到正常的时刻**（v1 起补；旧包没有 = 未闭合） |

`overflow`（`session.end` 里）记录“写不进事件流”的丢弃：

| 键 | 含义 |
|---|---|
| `events.total` / `first_t_wall` / `limit` | 事件到上限后丢了多少条、从哪一刻开始、上限值 |
| `checkpoints.total` / ... | 检查点到 400 后丢了多少个 |

`health` 汇总（`manifest.health`）：

| 字段 | 含义 |
|---|---|
| `dropped` / `checkpoint_dropped` | 丢弃条数（0 = 没触发上限） |
| `gaps_total_ms` | 已闭合缺口的时长之和 |
| `gaps_open` | 未闭合（没有 `t_end`）的缺口数 |
| `seq_gaps` | **真断档**（v1 起丢弃也占号，所以丢弃会在这里出现） |

`inspect_pack.py` 会把这些打成“完整性告警（这段可能没记全）”，不用翻 JSON。

**v1 补充**：`viewer.state-change` 新增 `trigger` 字段（`poll` = 轮询兜底，
`subscribe` = 订阅 state.changed 触发）；`config` 新增 `state_interval_ms` /
`semantic_watch` / `semantic_debounce_ms` / `max_events`。旧包没有这些字段，按默认值读。

**v1 新增事件**：`viewer.dwell`（停留）——`duration_ms`、`center`（100nm 取整）、
`segments`、`visible_layers`、`state_id`。它表示“人在这组视图/选中上停了多久”，
与 `keyframe` 里 `moment=dwell` 的图一一对应。

## 草稿（未保存的会话）

```text
results/manual_sessions/_draft_<session_id>/
  events.jsonl     增量追加（只写 seq 大于已收的）
  notes.jsonl      备注（整份覆盖）
  shots/*.png      关键帧图（也增量传，按 shot_id 去重）
  shots/shots.jsonl
  draft.json       session_id / config / counts / time / last_seq / updated_wall_ms
```

`POST /draft` 由采集器每 30 秒（`draft_ms`，可调）调用一次；正式 `POST /save`
成功后服务端删掉同 session 的草稿。恢复用 `nx.py recover`。
